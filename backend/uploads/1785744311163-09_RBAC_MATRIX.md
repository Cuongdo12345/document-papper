## Role map

### ADMIN
`Object.values(PERMISSIONS)` + `SYSTEM_ADMIN`.

Ngoài ra middleware còn bypass toàn bộ nếu:
```text
role.name === "ADMIN"
```

Khi merge Medical Equipment permissions vào `PERMISSIONS` thật, ADMIN sẽ tự động
nhận đủ 13 permission mới qua `Object.values(PERMISSIONS)` — không cần khai báo
riêng (đã verify bằng test: seed script gán đủ 13/13 cho ADMIN).

### IT
Có:
- Document create/update/detail.
- Audit view.
- Department CRUD.
- User change password.
- Asset view/detail/create/update/delete/assign/alerts/excel/inventory.
- Asset category CRUD trừ permanent delete.
- **[MỚI — DESIGN]** Medical Equipment: `VIEW / VIEW_DETAIL / CREATE / UPDATE / DELETE / RELOCATE / CALIBRATE` (10 quyền).
- **[MỚI — DESIGN]** Medical Equipment Category: `VIEW / CREATE / UPDATE` (không có DELETE).

Không có:
- `DOCUMENT_VIEW` trong role map.
- `ASSET_DELETE_PERMANENT`.
- `ASSET_CATEGORY_DELETE_PERMANENT`.
- **[MỚI — DESIGN]** `MEDICAL_EQUIPMENT_DELETE_PERMANENT`.
- **[MỚI — DESIGN]** `MEDICAL_EQUIPMENT_QUARANTINE_OVERRIDE`.
- **[MỚI — DESIGN]** `MEDICAL_EQUIPMENT_CATEGORY_DELETE`.

Lý do (nhất quán với pattern Asset): 3 quyền trên có tính "phá hủy vĩnh viễn" hoặc
"ghi đè safety gate" — chỉ ADMIN nắm giữ ở giai đoạn đầu (INFERRED, an toàn nhất,
dễ nới quyền sau — xem 18_MEDICAL_EQUIPMENT_DESIGN.md §6).

### USER
Có:
- `ROLE_CREATE`  ← **rất đáng chú ý, cần xác nhận**.
- Document CRUD/view/detail.
- User change password.
- Asset view/detail.
- Asset category view.
- Asset inventory check.
- **[MỚI — DESIGN]** Medical Equipment: `VIEW / VIEW_DETAIL` (chỉ xem, 2 quyền).
- **[MỚI — DESIGN]** Medical Equipment Category: `VIEW` (chỉ xem).

## Route permission drift

| Route permission | Có trong constants? |
|---|---|
| USER_CREATE | Có |
| USER_READ | **Không** |
| USER_DETAIL | **Không** |
| USER_UPDATE | Có |
| USER_DELETE | Có |
| USER_RESTORE | Có |
| USER_CHANGE_PASSWORD | Có |
| USER_RESET_PASSWORD | Có |
| DOCUMENT_CREATE | Có nhưng route create đang comment |
| DOCUMENT_READ | **Không** |
| DOCUMENT_DETAIL | **Không** |
| DOCUMENT_UPDATE | Có |
| DOCUMENT_DELETE | Có |
| POLICY_CREATE | **Không** |
| POLICY_VIEW | **Không** |
| POLICY_UPDATE | **Không** |
| POLICY_DELETE | **Không** |
| DASHBOARD_READ | **Không** |

> Bảng trên chỉ phản ánh route **đã tồn tại trong code thật** (`backend.zip`).
> Medical Equipment chưa có route nào được viết, nên chưa xuất hiện ở bảng này —
> khi viết route, PHẢI dùng đúng 13 constant đã định nghĩa ở trên, không dùng raw
> string, để không lặp lại chính vấn đề mà bảng này đang ghi nhận.

## Kết luận

RBAC hiện tại có **hai nguồn sự thật**:
1. constants/role map;
2. raw permission strings trong route.

Phải hợp nhất về một source of truth.

Medical Equipment permissions (13 permission, role map IT/USER) đã được thiết kế
theo đúng single-source-of-truth ngay từ đầu (permission constant object, không
dùng raw string ở bất kỳ đâu kể cả seed script) — xem `18_MEDICAL_EQUIPMENT_DESIGN.md`
§6, §12, §13 và các file code trong `constants/medicalEquipment.*.ts`,
`seeds/medicalEquipment.permission.seed.ts`. Mục tiêu: không lặp lại SEC-002/D-010
ở module mới này.
