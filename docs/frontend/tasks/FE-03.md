# FE-03 — Users / Departments UI thật

> Trạng thái: **DONE** (2026-09-05). Nền tảng dùng lại nguyên vẹn từ FE-01 (App Shell, Design System) + FE-02 (RBAC UI Foundation) — không redesign, không đổi kiến trúc.

## Objective

Thay `PlaceholderPage` ở `/app/users` và `/app/departments` bằng UI thật: danh sách (filter/sort/pagination), tạo/sửa, các action quản trị riêng (gán role, reset mật khẩu, vô hiệu hoá/khôi phục cho Users; xoá cho Departments) — permission-aware, đúng "Shared Page Pattern" đã định nghĩa ở `FE_UI_DEVELOPMENT_ROADMAP.md`.

## Blocker phát hiện trước khi code (đã xử lý riêng — xem `docs/development/tasks/DEV-027.md`)

1. **RBAC**: 0 role ngoài ADMIN có `USER_VIEW`/`USER_VIEW_DETAIL` → hỏi user, quyết định cấp thêm cho role `IT` (chỉ xem, không CRUD).
2. **Bug nghiêm trọng**: `validateQuery` middleware crash 500 trên MỌI route dùng nó (Express 5, `req.query` là accessor getter-only) — chặn thẳng `GET /users`. Đã sửa + có test hồi quy.

Cả 2 đã DONE trước khi bắt đầu code FE-03 — không phải phạm vi FE-03 nhưng là điều kiện tiên quyết.

## API Contract đã xác nhận qua source (không suy đoán)

- `GET /users`/`GET /users/:id` (`users.service.ts:getList/getById`): **CHỈ populate `department`**, **role GIỮ NGUYÊN ObjectId thô** — khác `GET /users/me` (đã populate đầy đủ, DEV-026). FE phải tự resolve tên role qua `GET /rbac/roles`.
- `POST /users` (`create`): chặn tạo user với role ADMIN/`isSystemRole`; role `USER` bắt buộc `department`.
- `PUT /users/:id` (`update`): KHÔNG có `password`/`isActive` trong whitelist thực tế — đổi mật khẩu và kích hoạt/vô hiệu hoá là 2 action RIÊNG (endpoint khác), generic update không được phép bypass business rule của 2 action đó.
- `PATCH /users/:id/role` (`assignRole`, permission riêng `USER_ASSIGN_ROLE`): chặn tự đổi role chính mình, chặn gán ADMIN.
- `DELETE /users/:id` (`disable`, soft-delete): chặn disable ADMIN, chặn nếu user còn tài sản đang gán, thu hồi toàn bộ refresh token (logout mọi thiết bị).
- `PATCH /users/restore/:id`, `PATCH /users/reset-password/:id` — như tên gọi.
- Response shape KHÔNG đồng nhất: `GET /users` dùng `message` (giá trị `true`, KHÔNG phải string!), phần lớn endpoint User khác dùng `message` (string).
- `department.model.ts` **CHỈ CÓ `code`+`name`** — KHÔNG có `description`/`isActive` như `UI_REQUIREMENTS.md` từng suy đoán (đã sửa nhận thức, xem `types/department.types.ts`).
- `GET /departments` dùng `success` (string) thay vì `message`; 4 endpoint Department còn lại (detail/create/update/delete) dùng `message` — 2 quy ước khác nhau THẬT trong cùng 1 controller, đã verify trực tiếp source.
- `DELETE /departments/:id` — hard delete thật, backend tự chặn (400) nếu còn user/document/asset thuộc khoa.

## Implemented

### Shared components mới (`components/shared/`)
- `DataTable` — generic, theo đúng "Table UX Rules": server-side sort (click header, không tự sort client), skeleton loading (`LoadingState`), `EmptyState`, `ErrorState`+retry. Pagination tách riêng.
- `Pagination` — "Hiển thị X–Y / Total" + prev/next, dùng đúng field `totalPages` (DEV-025).
- `FilterBar` — layout wrapper nhẹ (children-based), KHÔNG phải config-engine (quyết định có ghi chú trong `SHARED_COMPONENTS_LIBRARY.md`).
- `ConfirmDialog` — compose `AppModal`, hỗ trợ `requireTypedConfirm` (chưa dùng ở FE-03).
- `StatusBadge` — sửa nhỏ: thêm optional prop `title` (dùng bởi `PermissionBadge` từ FE-02, không ảnh hưởng usage cũ).

### Hook mới
- `hooks/useDebounce.ts` — debounce input tìm kiếm (đã dự trù ở `FE_ARCHITECTURE.md`).
- `features/rbac/hooks/useRoles.ts` — `useRoles()` (danh sách đầy đủ) + `useAssignableRoles()` (lọc bỏ ADMIN/isSystemRole — backend chặn cứng gán 2 loại này).
- `features/users/hooks/` — `useUsers`, `useCreateUser`, `useUpdateUser`, `useAssignUserRole`, `useDisableUser`, `useRestoreUser`, `useResetUserPassword`.
- `features/departments/hooks/` — `useDepartments`, `useCreateDepartment`, `useUpdateDepartment`, `useDeleteDepartment`.
- Quy ước lỗi: mutation gắn **form** (Create/Update) KHÔNG tự toast lỗi trong hook — component đọc `mutation.error` qua `parseApiError()` hiện inline (giống Login/Reset Password). Mutation gắn **quick action** (assign role/disable/restore/reset password/delete department — trigger từ nút + ConfirmDialog, không có form) toast trong hook (giống `useLogout.ts`).

### API layer mới
- `api/users.api.ts`, `api/departments.api.ts`, `api/rbac.api.ts` (chỉ `getRoles`, đọc — KHÔNG phải RBAC Admin đầy đủ).
- `utils/unwrapResponse.ts` — sửa nhỏ: nới lỏng type `message` từ `string` sang `unknown` (response thật của `GET /users` trả `message:true` — boolean, không phải string). KHÔNG đổi runtime logic (hàm chưa từng đọc `message`).

### Types mới
- `types/user.types.ts`, `types/department.types.ts`, `types/rbac.types.ts` (Role — chỉ đủ cho dropdown/resolve tên, KHÔNG phải RBAC Admin).

### Pages/Components
- `features/users/pages/UsersListPage.tsx` — filter (keyword/role/trạng thái), sort (username/fullName/createdAt), cột Vai trò tự resolve tên qua `useRoles()`, action Sửa/Gán role/Đặt lại mật khẩu/Vô hiệu hoá-Khôi phục — mỗi action bọc `PermissionGuard` riêng.
- `features/users/components/UserFormDrawer.tsx` — `AppDrawer` (đúng khuyến nghị "User edit đầy đủ" trong `SHARED_COMPONENTS_LIBRARY.md`), 2 schema Zod (Create có password min8+username min5; Edit không có password/isActive).
- `features/users/components/AssignRoleModal.tsx`, `ResetPasswordModal.tsx` — `AppModal` riêng, pattern `key={user._id}` remount thay `useEffect` (tránh cascading render, theo khuyến nghị oxlint `set-state-in-effect`).
- `features/departments/pages/DepartmentsListPage.tsx`, `features/departments/components/DepartmentFormModal.tsx`.
- `routes/index.tsx` — thay `PlaceholderPage` bằng `UsersListPage`/`DepartmentsListPage` tại đúng route đã có sẵn (`/app/users`, `/app/departments`), KHÔNG đổi cấu trúc route/layout.

## Business rules KHÔNG tự suy diễn (để backend enforce, FE không duplicate)

- "Department bắt buộc nếu role là USER" — chỉ ghi chú UI (`<p className="text-xs">`), KHÔNG duplicate validate client (backend là nguồn cuối, message lỗi backend đã đủ rõ nếu thiếu).
- Role ADMIN bị loại khỏi mọi dropdown gán role (`useAssignableRoles`) — khớp đúng safeguard `role.isSystemRole===true || role.name==="ADMIN"` lặp lại ở 3 nơi backend (`create`/`update`/`assignRole`).
