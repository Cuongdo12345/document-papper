## 2. Backend — API mới (additive, không đổi endpoint cũ)

| Endpoint | Permission | Việc gì |
|---|---|---|
| `POST /api/notifications/broadcast` | `NOTIFICATION_BROADCAST` (mới) | Soạn + gửi `type:SYSTEM` tới `scope`: `ALL` / `ROLE` (`roleName`) / `DEPARTMENT` (`departmentId`) / `USERS` (`userIds[]`, tối đa 200) |
| `GET /api/notifications/admin` | `NOTIFICATION_VIEW_ALL` (mới) | Xem thông báo của BẤT KỲ user nào (filter `recipient`/`isRead`/`type`, phân trang) |

- 2 permission mới thêm vào `permission.constant.ts`, **KHÔNG gán thêm cho role nào** ngoài ADMIN — ADMIN tự động có qua `[...Object.values(PERMISSIONS)]` ở `rolePermission.map.ts` (đúng nguyên tắc đã áp dụng cho `ROLE_VIEW`/`PERMISSION_VIEW`, không sửa file role map).
- `broadcastNotificationService` **tái dùng nguyên `notifyUserIds`** (helper đã chạy ổn định cho 4 module khác — workflow/document/excel/rbac) — chỉ thêm bước `resolveBroadcastRecipientIds()` để đổi `scope` → danh sách `_id` user thật (luôn re-validate `isActive:true`, không tin payload client).
- `getAllNotificationsAdmin` là hàm HOÀN TOÀN MỚI, KHÔNG sửa `getNotificationsForUser` (self-scope) — 2 đường tách biệt, permission khác nhau là ranh giới bảo mật duy nhất.
- DTO: `BroadcastNotificationDTO` (Zod `.superRefine` validate field bắt buộc theo `scope`), `QueryAllNotificationsDTO`.
- Route order: `GET /admin`/`POST /broadcast` đặt cạnh các route GET/POST tĩnh khác, trước `PATCH /:id/read` — không xung đột (khác HTTP method/path).

**Phát hiện + sửa thêm 3 lỗi tài liệu OpenAPI có sẵn TRƯỚC task này** (phát hiện khi đối chiếu đúng section đang sửa, theo CLAUDE.md Mục 17):
1. `GET /notifications` response từng khai sai `data.pagination` (object lồng) — thực tế field PHẲNG (`total/page/limit/totalPages` cùng cấp `items`).
2. `GET /notifications/unread-count` từng khai sai tên field `count` — thực tế là `unreadCount`.
3. Schema `Notification.type` thiếu giá trị enum thứ 11 (`MEDICAL_DEVICE_CALIBRATION_DUE`, có từ "Giai đoạn 3" nhưng chưa từng thêm vào doc).

## 4c. Bug tự phát hiện qua phản hồi user (2026-09-10, cùng ngày) — 2 permission mới KHÔNG có trong DB

User báo: vào UI không thấy nút "Gửi thông báo hệ thống" lẫn tab "Quản trị" dù đã đăng nhập ADMIN. Kiểm tra lại đúng: đây là lỗi thiếu sót của chính task này, KHÔNG phải bug ở component.

- **Root cause**: `usePermission()` (FE) đọc `user.permissions` từ `GET /users/me` → tính qua `getUserEffectivePermissions()` (`permission.service.ts`) — hàm này đọc `role.permissions`, mảng ObjectId trỏ tới collection `Permission` THẬT trong MongoDB. `rolePermission.map.ts` (nơi Mục 2 ở trên đã thêm `NOTIFICATION_BROADCAST`/`NOTIFICATION_VIEW_ALL` vào `ADMIN: [...Object.values(PERMISSIONS)]`) **chỉ là nguồn cho `scripts/seed-rbac.ts`** — không tự động ghi vào DB. Vì chưa từng chạy seed / tạo tay 2 Permission này + gán cho role ADMIN trong DB, `GET /users/me` trả về thiếu 2 quyền → FE tự ẩn đúng theo PermissionGuard (không phải lỗi hiển thị).
- Backend API (`/broadcast`, `/admin`) KHÔNG bị ảnh hưởng — `authorizePermission.middleware.ts` bypass toàn bộ permission check cho role `ADMIN`/`isSystemRole`, nên gọi trực tiếp vẫn hoạt động. Đây THUẦN là lỗ hổng hiển thị ở FE do dữ liệu RBAC trong DB chưa đồng bộ.
- **Sửa (ban đầu)**: đề xuất KHÔNG tự chạy `seed-rbac.ts` (SET LẠI TOÀN BỘ `permissions` của MỌI role theo code — rủi ro ghi đè nếu role nào đã bị chỉnh tay khác code, đúng tình huống DEV-034 từng gặp, lúc đó cũng chọn gọi API assign cho 1 role thay vì reseed toàn bộ). Hướng dẫn user tự làm qua RBAC Admin UI có sẵn (FE-08).
- **User yêu cầu trực tiếp chạy script** (cùng ngày) — đã chạy `npx ts-node scripts/seed-rbac.ts` sau khi xác nhận `MONGO_URI` trỏ DB local (`127.0.0.1:27017`, không phải remote/prod). Kết quả: 3 Permission tạo mới (`NOTIFICATION_BROADCAST`, `NOTIFICATION_VIEW_ALL`, và `PERFORMANCE_VIEW` — permission cũ từ DEV-011 hoá ra cũng chưa từng được seed, phát hiện phụ ngoài scope, không cần sửa gì thêm), 7/7 role được set lại permissions theo đúng `rolePermission.map.ts` (ADMIN: 80 permission), cache permission toàn bộ user đã bị xoá. Verify riêng bằng query Mongo trực tiếp: role ADMIN đã có cả 2 permission mới. Không còn cần thao tác tay qua UI nữa — user chỉ cần đăng nhập lại (hoặc đợi cache tự tính lại) để thấy đủ UI.
- Đã bổ sung mô tả tiếng Việt cho 2 permission này vào `PERMISSION_DESCRIPTIONS` (`scripts/seed-rbac.ts`) — thay đổi an toàn, thuần additive, không tự chạy script — để môi trường nào seed lại/mới từ đầu sẽ có mô tả đúng thay vì fallback tự động.
