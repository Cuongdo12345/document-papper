## 4. Auth Foundation

- **Token handling**: `accessToken` in-memory (Zustand `authStore`), `refreshToken` trong `localStorage` qua `utils/tokenStorage.ts` (module riêng, không qua Zustand) — đúng `FE_FOUNDATION_SPEC.md` Mục 7.
- **Refresh**: `api/axios.ts` gọi `/auths/refresh-token` bằng **axios gốc** (không phải `axiosInstance`) để tránh đệ quy qua interceptor.
- **Refresh-lock**: có — 1 biến module-level `refreshPromise`, dùng CHUNG cho mọi request 401 xảy ra đồng thời (không tạo N request refresh cho N request 401 cùng lúc).
- **401 handling**: retry request gốc 1 lần sau khi refresh thành công; refresh thất bại HOẶC chính request `/refresh-token` trả lỗi → `performLogout()` (xoá state + `refreshToken`, redirect `/login`), không loop vô hạn (`_retry` flag chặn retry lần 2).

## 5. Error Handling

- **Response normalization**: `unwrapResponse<T>()` — xử lý 2 shape chuẩn (`{success,data,pagination?}` / `{message,data}`). KHÔNG dùng cho Auth login/refresh (response phẳng, đọc trực tiếp field) hoặc domain Upload (dùng hàm riêng khi code tới, chưa cần ở FE-00).
- **API errors**: `parseApiError()` — 3 nhánh (chuẩn `success:false` phân theo `errorCode`, Upload chỉ `{message}`, network error/timeout) — **đã verify với response lỗi THẬT** lấy từ backend đang chạy (401/400), không phải suy đoán từ tài liệu.
- **Validation errors**: phân biệt `BAD_REQUEST` (Zod, `details[].path` là mảng) vs `VALIDATION_ERROR` (Mongoose, `details` là `string[]` thuần).

## 10. Issues (conflict tìm được khi verify — KHÔNG tự sửa KB/backend)

1. **⚠️ QUAN TRỌNG — chặn RBAC UI thật**: `GET /users/me` (`getMeService`, `backend/src/services/users/users.service.ts:490-501`) chỉ `.populate("role","name")` — response **KHÔNG có `role.isSystemRole`**, và `extraPermissions`/`denyPermissions` là **ObjectId thô** (không populate thành permission string). **KHÔNG có field `permissions: string[]` computed nào được trả về** — trái với mô tả ở `AUTH_RBAC_MAP.md` Mục 1.3 ("Response: User đầy đủ, bao gồm role.isSystemRole, extraPermissions — nguồn CHÍNH để FE biết quyền/role thật") và Mục 2.3. FE hiện **không có cách nào** lấy effective-permission-list của user hiện tại từ bất kỳ endpoint nào đã biết. `usePermission()` đã implement foundation-only: `isAdmin` (dựa `role.name`) đáng tin cậy, `hasPermission()` luôn trả `false` cho non-ADMIN kèm cảnh báo dev — KHÔNG tự chế field không tồn tại.
2. `POST /auths/refresh-token` với token invalid trả **400** (`errorCode:"BAD_REQUEST"`), KHÔNG phải 401 như `AUTH_RBAC_MAP.md` Mục 1.2 mô tả — đã verify bằng request thật (Mục 6). Không ảnh hưởng code thực thi (nhánh xử lý trong `api/axios.ts` check theo `url` chứ không phụ thuộc status cụ thể), nhưng tài liệu KB cần sửa lại cho đúng `SOURCE_CODE_BEHAVIOR`.
3. `GET /users/me` response có field `success` là **STRING** (`"Lấy thông tin cá nhân thành công"`, message thật), KHÔNG phải boolean — `user.controller.ts:getMe`. Thêm 1 biến thể response shape chưa từng ghi ở `ERROR_HANDLING.md`/`API_REFERENCE.md`. Không ảnh hưởng `unwrapResponse()` (chỉ đọc field `data`), nhưng KHÔNG dùng field `success` của response này cho logic rẽ nhánh.
4. `POST /auths/login` — `user` trả về là SUBSET hẹp hơn `CurrentUser` (`auths.service.ts:login()`, chỉ `{_id, username, fullName, role, department}`, thiếu `email`/`isActive`/`extraPermissions`/`denyPermissions`) — khác object đầy đủ hơn từ `getMeService`. Đã xử lý bằng 2 type riêng (`LoginUser` vs `CurrentUser`) + seed cache tạm rồi để React Query tự refetch đầy đủ hơn ngay sau đó — không phải bug, chỉ cần tách type đúng.
5. shadcn CLI mới (v4.21) đổi hoàn toàn UX (preset Nova/Vega/Maia..., yêu cầu chọn tương tác) — không tương thích môi trường non-interactive. Đã bỏ CLI, dựng foundation thủ công.
