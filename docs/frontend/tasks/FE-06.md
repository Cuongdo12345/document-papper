# FE-06 — Assets Core UI

> Ngày: 2026-09-06. Status: **DONE** (increment đầu tiên). Nguồn gốc: tiếp nối roadmap sau FE-05 (Workflow UI) — user yêu cầu "kiểm tra lại và xem chuẩn bị làm phần tiếp theo UI"; xác nhận qua `FRONTEND_MEMORY.md`/`FE_UI_DEVELOPMENT_ROADMAP.md` Mục 29: thứ tự tiếp theo sau Workflow là **Assets**.

## Objective

Xây dựng UI đầy đủ cho domain Asset: danh sách, chi tiết, tạo/sửa, cấp phát/luân chuyển/thu hồi + lịch sử — theo scope Mục 12 `FE_UI_DEVELOPMENT_ROADMAP.md` ("Assets UI").

## Scope quyết định (đã CHỦ Ý loại trừ, không phải quên)

Theo đúng thứ tự phase độc lập trong roadmap (Mục 29: Assets → Medical Devices → RBAC Admin → Dashboard → ... → Upload/Excel), 3 phần sau **KHÔNG** nằm trong task này, để lại cho phase riêng:

1. **Asset Categories CRUD đầy đủ** (roadmap Mục 14) — FE-06 chỉ dùng `GET /assets/asset-categories` (list tối thiểu) để phục vụ dropdown chọn danh mục khi tạo/sửa Asset, giống hệt cách FE-04 dùng `useDepartments` list-only trước khi FE-03 làm Departments CRUD đầy đủ.
2. **Medical Device Profile / Calibration** (roadmap Mục 13) — không có tab/section nào trong Asset Detail cho phần này.
3. **Excel import/export, QR code, check-in kiểm kê** (`Giai đoạn 5` backend, thuộc roadmap Mục 20 "Upload/Excel UI", 1 phase riêng biệt sau) — không có nút/trang nào cho `ASSET_EXCEL_IMPORT/EXPORT`, `ASSET_INVENTORY_CHECK`, QR code dù các endpoint này đã có sẵn ở backend.
4. **Xoá vĩnh viễn** (`ASSET_DELETE_PERMANENT`) — rủi ro cao, không có UI, giống cách Document cũng không có UI xoá vĩnh viễn.

**Lỗi phát hiện qua `npm run build` (không phải qua `tsc --noEmit` — 2 lệnh dùng config khác nhau)**: `purchasePrice: z.union([z.coerce.number().nonnegative(), z.literal("")])` khiến `zodResolver` suy luận input/output type lệch nhau (`unknown` vs `number`), `useForm<T>` không compile được. Sửa: đổi field này thành `z.string().optional().refine(...)` thuần (không `z.coerce`), parse `Number(...)` thủ công lúc submit — áp dụng cho cả `AssetEditModal.tsx` và `AssetCreatePage.tsx`.

**Chưa test bằng trình duyệt thật / HTTP thật** (không có công cụ điều khiển browser trong phiên này, và đây là tính năng MỚI hoàn toàn — không có "trước/sau" để so sánh qua HTTP như các fix trong phiên) — khuyến nghị user tự trải nghiệm luồng: xem danh sách → tạo mới → xem chi tiết → cấp phát → luân chuyển → thu hồi → xem lịch sử, với ít nhất 2 tài khoản (`IT` hoặc `PHONG_VAT_TU_TTB`, đều có `ASSET_CREATE`/`ASSET_ASSIGN`).
