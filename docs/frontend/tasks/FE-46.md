- **Nút theo quyền:** danh sách (Thêm tài sản, Quét mã kiểm kê, Lịch bảo trì, Sửa/Xoá ở từng dòng), chi tiết (Sửa, Xoá, khối Cấp phát, Tạo hồ sơ CNTT), danh mục (Thêm danh mục, Xoá), bản quyền phần mềm (Thêm bản quyền).

Bảng kỳ vọng nằm trong `role-permissions.spec.ts`, viết TAY từ `ASSET_MODULE_SPLIT_PLAN.md` mục 4.4 + 2 quyết định của user (IT đủ quyền module CNTT và được thanh lý) — không import từ code frontend để bắt lỗi ánh xạ quyền ↔ giao diện. **Khi đổi quyền của role, phải sửa bảng này.** Tổng: 58 test + setup + teardown.

## 2. Thiết kế

- `frontend/e2e/roles/` (mới): `roles.shared.ts` (hằng số + hàm API), `roles.setup.ts`, `role-permissions.spec.ts`, `roles.teardown.ts`.
- **Setup** (ADMIN qua API): tạo 1 khoa, danh mục gốc+lá và 1 thiết bị cho mỗi module, 3 tài khoản (tên có hậu tố thời gian); rồi đăng nhập UI từng tài khoản và lưu phiên `e2e/.auth/role-<ROLE>.json` (đã gitignore).
- **Teardown**: xoá mềm rồi xoá VĨNH VIỄN thiết bị (backend chặn xoá danh mục/khoa nếu còn tài sản tham chiếu, kể cả đã xoá mềm), xoá danh mục, tài khoản (xoá mềm), khoa/phòng. Mỗi bước độc lập, gom lỗi báo cuối.
- **Vì sao project riêng:** nhóm cũ (a11y, visual, asset-split) chạy bằng ADMIN trên DB trống; ảnh baseline Dashboard/Người dùng phụ thuộc số khoa/phòng và số người dùng. `playwright.config.ts` có 4 project: `chromium` (nhóm cũ, `testIgnore` roles) → `roles-setup` (phụ thuộc `chromium`, `teardown: roles-teardown`) → `roles` → `roles-teardown`. `storageState` ADMIN chuyển từ `use` chung vào project `chromium`.
- Chạy riêng nhóm role: `npm run test:roles` (bỏ qua `chromium`, vẫn chạy setup → spec → teardown).
- **Tắt bộ giới hạn đăng nhập/làm mới token ở backend Playwright** (`backend/src/__tests__/e2e/startPlaywrightServer.ts`, test-only): xem mục 4.

## 4. Giới hạn đăng nhập/làm mới token (429) — quyết định của user

`authRateLimiter` (100 lượt / 15 phút / IP, dùng chung cho `/login` và `/refresh-token`): mỗi lần mở trang trong test tốn 1 lượt làm mới token. Đo sau lượt chạy trọn bộ: `RateLimit-Remaining: 0` → bộ test dùng ~99/100 lượt; chạy dồn nhiều lượt trên một backend giữ nguyên đã gây 1 lỗi 429 thật làm hỏng 1 test visual. User chọn (2026-11-02): **thay `authRateLimiter` bằng bản cho qua CHỈ trong `startPlaywrightServer.ts`** (vá `exports` trước khi nạp `app`). Không đổi code production; sau khi vá, backend Playwright không còn trả header `RateLimit-*`.
- Bộ đếm theo IP vẫn có test (`trust-proxy.e2e-test.ts`), nhưng việc **trả 429 khi vượt ngưỡng hiện chưa có test tự động nào** — ghi nhận, không sửa trong task này.
