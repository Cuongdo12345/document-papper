Hỗ trợ `mode="any"|"all"` (mảng permission) + `fallback`. Ghi rõ trong code: **CHỈ là UX/UI visibility layer**, backend (`authorizePermission.middleware.ts`) luôn là ranh giới bảo mật thật.

## Authentication

Flow KHÔNG đổi kiến trúc so với FE-00 (đã đúng từ đầu), chỉ hoàn thiện phần còn thiếu:

```
LoginPage → useLogin() → POST /auths/login → {accessToken, refreshToken, user(subset)}
  → authStore.login() (accessToken in-memory) + tokenStorage (refreshToken localStorage)
  → seed React Query cache ["users","me"] tạm bằng user subset
  → navigate /app
  → useCurrentUser() tự refetch GET /users/me (đầy đủ, có permissions[])

Request bất kỳ → 401 → refresh-lock (1 promise dùng chung N request 401 đồng thời)
  → POST /auths/refresh-token → accessToken mới → retry TẤT CẢ request đang chờ
  → refresh thất bại (kể cả chính request /refresh-token) → performLogout() → /login

Logout → POST /auths/logout (best-effort, lỗi mạng vẫn logout cục bộ + toast cảnh báo)
  → clear authStore + tokenStorage + React Query cache → /login (qua Header/DashboardPage)
```

**Session restore**: reload trang → `accessToken` mất (in-memory) → request đầu tiên cần auth → 401 → refresh bằng `refreshToken` (localStorage) → accessToken mới → `useCurrentUser()` tự fetch lại. Không có "restore token lúc app khởi động" riêng — refresh-lock tự xử lý transparent ở request đầu tiên.

## RBAC

- **Nguồn DUY NHẤT**: `user.permissions: string[]` từ `GET /users/me` (DEV-026, effective permission đã tính sẵn ở backend).
- **`usePermission()`**: `hasPermission(p)`, `hasAnyPermission([...])`, `hasAllPermissions([...])` — TOÀN BỘ chỉ đọc mảng, KHÔNG tính lại `role.permissions ∪ extraPermissions − denyPermissions`, KHÔNG special-case ADMIN/isSystemRole.
- **`isSystemRole`**: expose riêng, CHỈ để hiển thị (badge) — không ảnh hưởng `hasPermission()`.
- **`PermissionGuard`**: UX/UI visibility layer — ẩn/hiện, KHÔNG PHẢI security boundary (nhắc lại trong code + doc).
- **Test bắt buộc** (Mục 45 spec gốc) — xem Mục Tests, đã PASS đầy đủ 3 case.
