# FE-35 — Thanh chọn nhiều chỉ hiện hành động áp dụng được (Xoá / Khôi phục)

**Ngày:** 2026-09-27
**Trạng thái:** DONE (phần FE). User gửi ảnh trang Khoa/Phòng: đang ở bộ lọc "Đang hoạt động", chọn nhiều
dòng thì thanh `BatchActionBar` vẫn hiện cả "Khôi phục" — yêu cầu nút Khôi phục chỉ hiện ở danh sách đã ẩn,
đồng bộ cho mọi trang liên quan.

## 1. Đã hỏi trước khi làm (AskUserQuestion)

- Nút **Xoá** ở danh sách đã ẩn: user chọn **ẩn luôn** (đối xứng — xoá lại dòng đã xoá chắc chắn lỗi).
- Bộ lọc **"Tất cả"**: user chọn **theo dòng đang chọn** — có chọn dòng đã ẩn → hiện Khôi phục, có chọn dòng
  đang hoạt động → hiện Xoá.

Quy tắc "theo dòng đang chọn" bao luôn 2 trường hợp còn lại (danh sách đang hoạt động → chỉ có dòng đang
hoạt động → chỉ Xoá; danh sách đã ẩn → chỉ Khôi phục), nên dùng 1 quy tắc duy nhất cho cả 3 chế độ lọc.

## 2. Thay đổi

- MỚI `frontend/src/utils/splitSelectionByActive.ts` — tách id đang chọn thành `activeIds`/`inactiveIds`
  theo predicate của từng trang (+ 4 unit test `utils/__tests__/splitSelectionByActive.test.ts`).
- 8 trang dùng `BatchActionBar`: Tài liệu, Tài sản, Danh mục tài sản, Vật tư tiêu hao, Nhóm vật tư, Nhà cung
  cấp, Người dùng, Khoa/Phòng:
  - `onDelete` chỉ truyền khi `activeIds.length > 0`, `onRestore` chỉ khi `inactiveIds.length > 0` (vẫn giữ
    nguyên điều kiện quyền cũ của từng trang). `BatchActionBar` vốn đã ẩn nút khi prop `undefined` — không
    sửa component dùng chung.
  - Mutation hàng loạt chỉ gửi đúng nhóm id (`activeIds` cho xoá, `inactiveIds` cho khôi phục) thay vì toàn
    bộ selection — chọn lẫn không còn gửi id sai loại lên API (trước đây sẽ ra 1 loạt "thất bại").
  - Số lượng trong ConfirmDialog đếm đúng nhóm id sẽ gửi.
  - Predicate giữ đúng cách từng trang đang phân biệt dòng ở `rowActions`: `isActive !== false` (Assets,
    AssetCategories, ConsumableCategories, Departments) hoặc `!!isActive` (Documents, Vendors, Consumables,
    Users).
- 6 trang sửa bằng 1 script Node tạm (đọc/ghi UTF-8, có assert từng bước, đã xoá) — đã review `git diff`
  từng file.

## 3. Verify

- `tsc -b` 0 lỗi, `oxlint` giữ baseline 4, `vitest` 36/36 (+4), `npm run build` PASS, Playwright
  a11y+visual 16/16 PASS.
- Spot-check UI thật (Playwright tạm, đã xoá) trang Khoa/Phòng: "Đang hoạt động" chọn dòng → chỉ **Xoá**;
  "Đã ẩn" chọn dòng → chỉ **Khôi phục**. Ảnh chụp xác nhận.

## 4. Phát hiện: bộ lọc "Tất cả" KHÔNG hoạt động ở cả 8 trang (lỗi có sẵn, CHƯA sửa — đã hỏi user)

Bước kiểm tra chế độ "Tất cả" thất bại: dòng đã ẩn không xuất hiện. Nguyên nhân: FE gửi "Tất cả" dưới dạng
KHÔNG truyền `isActive`, còn backend coi "không truyền" = chỉ đang hoạt động:
`departments.service.ts:69`, `consumableCategory.service.ts:49`, `document.service.ts:273`,
`vendor.service.ts:38`, `asset.service.ts:78`, `consumableItem.service.ts:136`, `assetCategory.service.ts:140`
(`isActive === undefined ? true : isActive`), `users.service.ts:124` (`isActive === "false" ? false : true`).
→ "Tất cả" hiện đang giống hệt "Đang hoạt động". Logic "theo dòng đang chọn" ở FE đã đúng (unit test phủ
trường hợp chọn lẫn) nhưng chưa thể thấy trên UI cho tới khi "Tất cả" trả về đúng cả 2 loại. Sửa cần đổi
contract API (DTO + service backend của 8 domain) — ngoài phạm vi yêu cầu, đã báo user và chờ quyết định.
