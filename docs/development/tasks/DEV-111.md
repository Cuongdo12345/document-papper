## 1. Sao lưu DB dev

`scripts/backup-mongo.ps1` (có sẵn) dùng `mongodump`, nhưng máy dev **chưa cài MongoDB Database Tools** (chỉ có MongoDB Server). User chọn (AskUserQuestion): viết script Node xuất EJSON, không cài thêm gì.

Script mới (trong `backend/scripts/`, thư mục này bị `.gitignore` nên **không nằm trong git**):
- `backup-mongo-ejson.ts`: xuất từng collection ra file EJSON canonical (1 document/dòng, giữ đúng ObjectId/Date), sắp theo `_id`, kèm `manifest.json` (số bản ghi + định nghĩa index đầy đủ). Không tự xoá bản cũ (khác `backup-mongo.ps1` có xoay vòng 14 ngày).
- `restore-mongo-ejson.ts`: chỉ ghi vào DB **trống** (từ chối nếu DB đích đã có collection), tạo lại index theo manifest, so số bản ghi + tên index; có `--verify-only`.
- Chỉ sao lưu database; file tải lên ở `backend/uploads/` không nằm trong bản sao lưu (Giai đoạn 1 chỉ đụng DB).

**Bản sao lưu:** `D:\mongo-backups\ejson_hospital_documents_2026-10-08T01-42-27` — DB `hospital_documents`, 32 collection, 14.280 document (assets 119, assetcategories 46, medicaldeviceprofiles 15, calibrationrecords 6, operatorcertificates 3, contracts 23, assetassignmenthistories 110, documents 278, useraudits 10.839…).

**Đã kiểm chứng khôi phục được:**
1. Khôi phục vào DB tạm `hospital_documents_restore_check`: 32/32 collection khớp số bản ghi và tên index.
2. So **nội dung**: sha256 của từng dòng EJSON trong file so với document đọc lại từ DB tạm — 32/32 giống hệt; tuỳ chọn index giống hệt (vd TTL `refreshtokens.expiresAt_1` = 0, `assets.assetCode_1` unique). Kiểu dữ liệu giữ đúng (`_id`, `category`: ObjectId; `createdAt`: Date).
3. Đã xoá DB tạm (kiểm tên trước khi xoá; danh sách DB sau đó: admin, config, hospital_documents, local).

Cách khôi phục khi cần: `npx ts-node scripts/restore-mongo-ejson.ts "<thư mục sao lưu>" <tên DB trống>`, rồi trỏ `MONGO_URI` sang DB đó hoặc đổi tên thủ công. Script không bao giờ ghi đè DB đang có dữ liệu.
