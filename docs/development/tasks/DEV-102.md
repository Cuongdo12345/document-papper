# DEV-102 — BR-14: kiểm tra OTP 2FA atomic (chống vượt giới hạn 5 lần và dùng 1 mã nhiều lần)

**Ngày:** 2026-09-30
**Trạng thái:** DONE
**Loại:** SECURITY, BUG FIX

**Nguồn:** `docs/31_BACKEND_CODE_REVIEW.md` BR-14 (LOW).

## 1. Hiện trạng trước khi sửa

`services/auth/auths.service.ts`, hai hàm `verifyLoginOtp` (đăng nhập bước 2) và `confirmEnableTwoFactor` (bật 2FA), cùng làm theo kiểu: đọc OTP → kiểm tra `attempts >= 5` → so mã → `attempts += 1` → `save()`.

Vì không atomic, có 2 lỗi khi gửi request **song song**:
- **(a) Vượt giới hạn 5 lần thử (nội dung BR-14):** N request cùng đọc `attempts = 0`, cùng ghi `1`, nên cả loạt chỉ được đếm 1 lần.
- **(b) Dùng 1 mã nhiều lần (phát hiện thêm, user duyệt sửa cùng):** N request cùng mã **đúng** cùng thấy `used = false`. Đăng nhập ra N phiên; bật 2FA chạy N lần (N dòng audit).

Đã được giảm thiểu một phần nhờ rate limit 100 lần / 15 phút / IP (xem BR-08/DEV-096 về IP sau proxy).

## 2. Quyết định của user (AskUserQuestion)

- Sửa **cả lỗi (b)** trong cùng task, vì cùng nguyên nhân và cùng đoạn code.

## 3. Thay đổi

`auths.service.ts`: thêm hàm chung `checkOtpAtomically(otpId, code)`, dùng ở cả 2 nơi. Mỗi bước là 1 thao tác duy nhất phía MongoDB:
1. **Giành lượt thử:** `findOneAndUpdate({ _id, used: false, expiresAt > now, attempts < 5 }, { $inc: { attempts: 1 } })`. Chỉ tối đa 5 request giành được, bất kể song song bao nhiêu, nên tối đa 5 lần so mã. Trả `null` → `unavailable`.
2. **So mã** (bcrypt) với bản ghi vừa giành. Sai → `wrong`.
3. **Giành quyền dùng mã:** `updateOne({ _id, used: false }, { $set: { used: true } })`. Chỉ request thấy `modifiedCount = 1` được thành công; còn lại → `unavailable`.

Thông báo cho người dùng giữ nguyên, thêm 1 trường hợp: mã đã bị request khác chiếm/hết lượt giữa chừng → "Mã xác thực không hợp lệ hoặc đã hết hạn, vui lòng đăng nhập lại" (401 khi đăng nhập, 400 khi bật 2FA). Kiểm tra `attempts >= 5` ban đầu vẫn giữ làm lối tắt (thông báo cũ), còn đường atomic mới là chốt chặn thật.

Ghi chú hành vi: khi nhập **đúng**, `attempts` cũng tăng 1 (vì giành lượt trước khi so). Không ảnh hưởng, vì mã đã `used` ngay sau đó.

Không đổi API contract, frontend, OpenAPI, model hay index.
