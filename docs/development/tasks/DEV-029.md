# DEV-029 — Fix `POST /auths/logout` trả 500 (thiếu body → không revoke được refresh token)

> Ngày: 2026-09-06. Status: **DONE**. Nguồn gốc: user báo lỗi trực tiếp (screenshot DevTools Network) — bấm "Đăng xuất" vẫn logout được ở UI nhưng request `logout` trả **500**, kèm ảnh chụp DevTools xác nhận status/URL (`auth.api.ts:28`).

## Objective

Sửa lỗi 500 khi gọi `POST /auths/logout`, đảm bảo refresh token thực sự bị revoke ở DB (không chỉ xoá local state phía FE).

## Root Cause (BUG thật, không phải chỉ lỗi hiển thị)

Trace theo đúng chain Route → Middleware → Controller → Service (CLAUDE.md Mục 16):

1. **`frontend/src/api/auth.api.ts`** hàm `logout()` (trước sửa): gọi `axiosInstance.post("/auths/logout")` **không kèm body nào**.
2. **`backend/src/controllers/auth/auth.controller.ts:50`**: `logout` handler đọc thẳng `req.body.refreshToken` không guard tồn tại.
3. **`backend/src/routes/auth/auth.routes.ts:39`** (trước sửa): route `/logout` là route DUY NHẤT nhận body trong file nhưng KHÔNG có `validateBody` (khác `/refresh-token` cùng shape body `{refreshToken}`, có `validateBody(RefreshTokenDTO)`).
4. Vì không có data/Content-Type, Express để `req.body` là `undefined` → `req.body.refreshToken` ném `TypeError: Cannot read properties of undefined (reading 'refreshToken')` — không phải `ApiError`/`MulterError`/`CastError`/`ValidationError` → rơi vào nhánh fallback cuối (`backend/src/middlewares/error.middleware.ts:151-160`) → **500 "UNKNOWN_ERROR"**.
5. UI vẫn "trông như" logout thành công vì `frontend/src/features/auth/hooks/useLogout.ts` cố ý luôn xoá local state ở `onSettled` bất kể API lỗi (thiết kế đúng cho network failure, nhưng che mất bug thật này).
6. **Hệ quả thật**: `AuthService.logout()` (`backend/src/services/auth/auths.service.ts:308-326`) không bao giờ chạy tới `RefreshToken.findOneAndUpdate(..., {revoked:true})` — refresh token cũ vẫn còn hiệu lực server-side sau khi user bấm "Đăng xuất" (không bị thu hồi thật).

## Changes

### 1. `frontend/src/api/auth.api.ts`
`logout()` giờ gửi kèm body đúng shape backend cần để revoke:
```ts
export function logout(): Promise<AxiosResponse<{ message: string }>> {
  return axiosInstance.post("/auths/logout", {
    refreshToken: tokenStorage.getRefreshToken(),
  });
}
```
Tái dùng `tokenStorage` có sẵn (đã dùng ở `useLogout.ts`/`axios.ts::refreshAccessToken()`), không tạo utility mới.

### 2. `backend/src/routes/auth/auth.routes.ts`
Thêm `validateBody(RefreshTokenDTO)` cho route `/logout` — tái dùng DTO đã có (cùng shape với `/refresh-token`), không tạo DTO mới:
```ts
router.post("/logout", authenticate, validateBody(RefreshTokenDTO), logout);
```
Guard này đảm bảo `req.body.refreshToken` luôn là string không rỗng trước khi vào controller — nếu client (FE khác, mobile, script test...) vẫn gọi thiếu body trong tương lai, lỗi sẽ là 400 rõ ràng ("Dữ liệu gửi lên không hợp lệ") thay vì 500 mơ hồ.

## API Impact

`POST /auths/logout` — KHÔNG đổi contract response, chỉ đổi:
- **Request**: nay BẮT BUỘC body `{refreshToken: string}` (trước đây không validate, chấp nhận thiếu body nhưng crash 500 khi thiếu thật).
- Đây có thể coi là breaking change kỹ thuật cho bất kỳ consumer nào KHÁC ngoài FE hiện tại đang gọi `/auths/logout` không kèm body — nhưng consumer duy nhất trong repo là `frontend/src/api/auth.api.ts` đã được sửa đồng bộ. Không có FE thứ 2/mobile app nào khác trong repo.

## Database Impact

Không đổi schema. Hành vi runtime: `RefreshToken.revoked` giờ THỰC SỰ được set `true` khi logout (trước đây không bao giờ chạy tới do exception sớm hơn).

## Security Impact

**Cải thiện bảo mật thật**: trước fix, mọi lần "đăng xuất" đều để lại 1 refresh token còn hiệu lực trong DB (không bị revoke) — nếu refresh token đó bị lộ (XSS đọc localStorage, thiết bị dùng chung...), kẻ tấn công vẫn dùng được để lấy access token mới ngay cả sau khi chủ tài khoản đã "đăng xuất". Sau fix, refresh token bị revoke đúng thời điểm logout.
