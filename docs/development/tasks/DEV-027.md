# DEV-027 — Fix Critical `validateQuery` Bug (Express 5) + RBAC: IT thêm USER_VIEW/USER_VIEW_DETAIL

> Ngày: 2026-09-05. Status: **DONE**. Nguồn gốc: phát hiện khi bắt đầu code FE-03 (Users/Departments UI thật) — `GET /rbac/roles` trả 500 khi thử tra permission ID để cấp quyền IT.

## Objective

2 thay đổi backend độc lập nhưng phát hiện cùng lúc trong 1 phiên làm việc:

1. **Bug fix (nghiêm trọng, không kế hoạch)**: `validateQuery` middleware crash 500 trên MỌI route dùng nó, do incompatibility với Express 5.
2. **RBAC change (theo yêu cầu user)**: role `IT` được cấp thêm `USER_VIEW`/`USER_VIEW_DETAIL` (chỉ xem, không CRUD) để FE-03 có ý nghĩa thực tế hơn ADMIN-only.

## Phần 1 — Bug fix `validateQuery`

### Root Cause

`backend/src/middlewares/validate.middleware.ts` — dòng `req.query = result.data as any;`.

Project dùng **Express 5.2.1**. Trong Express 5 (`express/lib/request.js:217`), `req.query` được định nghĩa:
```js
defineGetter(req, 'query', function query(){ ... });
// defineGetter = Object.defineProperty(obj, name, {configurable:true, enumerable:true, get: getter})
```
**CHỈ có `get`, KHÔNG có `set`.** Gán trực tiếp `req.query = ...` (strict mode — TypeScript compile ra strict mode) throw:
```
TypeError: Cannot set property query of #<IncomingMessage> which has only a getter
```
Lỗi này bị `catchAsync`/error middleware bắt và trả về generic 500 (`"Đã có lỗi xảy ra, vui lòng thử lại sau"`, `errorCode: "UNKNOWN_ERROR"`) — không lộ ra stack trace nên rất khó nhận ra nguyên nhân thật nếu không đọc source `express/lib/request.js`.

`req.params`/`req.body` KHÔNG bị ảnh hưởng (đã verify: `req.params` không phải accessor — router gán trực tiếp mỗi request; `req.body` được `body-parser` gán bằng property thường, không qua `defineGetter`).

### Phạm vi ảnh hưởng (đã verify HTTP thật TRƯỚC khi sửa)

Mọi route có `validateQuery(...)` đều crash 500:
- `GET /api/users` ❌
- `GET /api/documents` ❌
- `GET /api/rbac/roles` ❌
- (suy luận hợp lý, cùng cơ chế: `GET /api/assets`, `GET /api/rbac/permissions`, `GET /api/rbac/policies`, `GET /api/audit-logs`, `GET /api/notifications`, `GET /api/uploads`... — mọi domain có query pagination/filter dùng chung `validateQuery`)

Route KHÔNG dùng `validateQuery` (vd `GET /api/departments`) không bị ảnh hưởng — đã verify vẫn 200 OK trước và sau fix.

### Fix

```ts
// backend/src/middlewares/validate.middleware.ts — validateQuery
Object.defineProperty(req, "query", {
  value: result.data,
  writable: true,
  configurable: true,
  enumerable: true,
});
```//thay cho `req.query = result.data as any;`. An toàn vì Express khai báo property này `configurable: true` — cho phép `Object.defineProperty` THAY THẾ accessor bằng 1 data property ghi được.

`validateBody`/`validateParams` — GIỮ NGUYÊN, không đổi (không bị lỗi này).

### Test mới

`backend/src/middlewares/__tests__/validate.middleware.test.ts` (**mới**, file trước đây chưa có test nào cho middleware này) — 5 test:
1. `validateQuery` không throw khi `req.query` là accessor getter-only (mô phỏng ĐÚNG hành vi Express 5 thật qua `Object.defineProperty` trên mock `req` — regression test cho chính bug này).
2. `req.query` sau validate chứa đúng data đã coerce (string → number).
3. Query không hợp lệ → `next(ApiError.badRequest)`, không throw.
4. `validateBody` vẫn hoạt động bình thường (không bị ảnh hưởng).
5. `validateParams` vẫn hoạt động bình thường (không bị ảnh hưởng).

## Phần 2 — RBAC: IT thêm USER_VIEW/USER_VIEW_DETAIL

### Lý do

FE-03 (Users UI) audit phát hiện: theo `rolePermission.map.ts`, **0 role ngoài ADMIN** có `USER_VIEW`/`USER_VIEW_DETAIL` → trang Users sẽ chỉ ADMIN dùng được. Hỏi user xác nhận — user chọn: cấp `USER_VIEW`+`USER_VIEW_DETAIL` (chỉ xem) cho role `IT`, KHÔNG cấp CRUD (create/update/delete/reset-password vẫn ADMIN-only).

Ghi chú: `rolePermission.map.ts` đã có sẵn 1 dòng bị comment `// PERMISSIONS.USER_VIEW_DETAIL,` trong khối IT — cho thấy thay đổi này từng được cân nhắc trước đó nhưng chưa bật.

### Changes

1. **Source** (`backend/src/shared/constants/rolePermission.map.ts`) — bỏ comment + thêm `PERMISSIONS.USER_VIEW`, `PERMISSIONS.USER_VIEW_DETAIL` vào mảng `IT`. File này CHỈ được đọc bởi `scripts/seed-rbac.ts` (seed script, không chạy tự động ở runtime) — sửa source KHÔNG tự áp dụng vào DB.
2. **DB thật (dev)** — áp dụng qua **API RBAC sẵn có** (`POST /rbac/roles/:id/assign-permissions`), **KHÔNG chạy `scripts/seed-rbac.ts`** (script đó SET LẠI TOÀN BỘ permissions của **MỌI role**, rủi ro cao hơn nhiều so với cần thiết cho 1 thay đổi nhỏ). Quy trình:
   - `GET /rbac/roles/:id` (role IT) → lấy 43 permission ID hiện có.
   - `GET /rbac/permissions?keyword=USER_VIEW` → lấy ID của `USER_VIEW`/`USER_VIEW_DETAIL`.
   - `POST /rbac/roles/:id/assign-permissions` với đúng 45 ID (43 cũ + 2 mới) — endpoint tự động `clearPermissionCacheForRole()`, có hiệu lực ngay, không cần đợi TTL cache 5 phút.

```

## API Impact

- `validateQuery` fix: KHÔNG đổi contract của bất kỳ endpoint nào — chỉ sửa lỗi khiến chúng crash. Response shape thành công giữ nguyên như thiết kế gốc.
- RBAC: KHÔNG đổi API — chỉ đổi DỮ LIỆU (permissions của 1 role trong DB), dùng đúng endpoint quản trị RBAC đã có sẵn.

## Database Impact

- `validateQuery` fix: không đổi schema.
- RBAC: `Role["IT"].permissions` (array ObjectId) — thêm 2 phần tử. Không destructive, không xoá permission nào đã có.

## Security Impact

- RBAC: IT chỉ được thêm quyền XEM (view), không CRUD — không mở rộng bề mặt tấn công/rủi ro ghi dữ liệu. `authorizePermission.middleware.ts` không đổi.
