# DEV-058 — Hợp đồng bảo trì: thêm Cập nhật / Huỷ (xoá mềm) / Khôi phục ở trang danh sách

**Ngày:** 2026-09-16. **Status:** DONE. **Nguồn gốc:** user gửi screenshot trang `/app/contracts`, báo
cột "Hành động" chỉ có nút xem chi tiết, thiếu Sửa/Xoá mềm/Khôi phục — yêu cầu phân tích và bổ sung,
cùng pattern đã làm cho Vendor (`VendorsListPage`) và Consumable (`ConsumablesListPage`).

## 1. Phát hiện quan trọng — KHÔNG thể copy y hệt Vendor/Consumable

Vendor/ConsumableItem dùng cờ chung `isActive: boolean`, toggle 2 chiều tự do qua 1 API update duy nhất.
`Contract` dùng vòng đời nghiệp vụ `status: "active" | "cancelled"`:

- `cancelContractService` (đã có từ DEV-057) là hành động MỘT CHIỀU — code cũ ghi rõ
  `cancelledAt/cancelledBy/cancelReason` là "BẤT BIẾN sau khi set". Không có API khôi phục.
- `updateContractService` từ chối sửa hợp đồng đã "cancelled" (giữ nguyên làm lịch sử).

→ Đã hỏi lại user qua AskUserQuestion (2 câu) trước khi code:

1. Có muốn xây API khôi phục thật (đổi thiết kế "huỷ = vĩnh viễn" cũ) hay chỉ dừng ở Cập nhật + Huỷ?
   User chọn: **có, muốn khôi phục được**.
2. Permission cho hành động khôi phục — dùng chung `CONTRACT_UPDATE` (như cancel) hay tách riêng?
   User chọn: **tách riêng `CONTRACT_RESTORE`** (kiểm soát chặt hơn ai được khôi phục).

## 2. Backend

- `services/vendors/contract.service.ts`: thêm `restoreContractService(contractId, userId?)` — chỉ chạy
  khi `status === CANCELLED` (400 nếu không), set lại `status = ACTIVE`, **unset**
  `cancelledAt/cancelledBy/cancelReason` (gán `undefined` — Mongoose tạo `$unset` khi `.save()`), cập nhật
  `updatedBy`.
- `interfaces/vendors/contract.interface.ts`: sửa lại comment cũ ("BẤT BIẾN tuyệt đối") — nay có thể bị
  unset bởi `restoreContractService`, `updateContractService` vẫn giữ nguyên không cho sửa hợp đồng đã huỷ.
- `controllers/vendors/contract.controller.ts`: thêm `restoreContract`.
- `routes/vendors/contract.routes.ts`: thêm `PATCH /:id/restore`, permission `CONTRACT_RESTORE` (không
  dùng `CONTRACT_UPDATE`), không cần body.
- `shared/constants/permission.constant.ts`: thêm `CONTRACT_RESTORE`.
- `shared/constants/rolePermission.map.ts`: gán `CONTRACT_RESTORE` cho IT + Phòng Vật tư-TTB (2 role đang
  có đủ `CONTRACT_CREATE/UPDATE` từ DEV-057) — KHÔNG gán cho role nào khác.
- `docs/openAPI.yaml`: thêm path `/api/contracts/{id}/restore`. Validate qua `js-yaml` — 117 paths.
- Test mới (`contract.service.test.ts`): 2 case cho `restoreContractService` (thành công — set đúng
  status/unset field; hợp đồng đang active → 400). Tổng backend: **290/290 PASS**.
- Đã chạy `scripts/seed-rbac.ts` (chế độ mặc định, an toàn — không `--sync-roles`) để thêm Permission

  thủ công qua UI "Phân quyền" mới dùng được nút Khôi phục (ADMIN không bị ảnh hưởng, bypass qua
  `isSystemRole`).

### Sự cố thao tác trong lúc làm (đáng ghi lại)

Khi archive tạm `scripts/seed-rbac.ts` để sửa, dùng `Get-Content | ForEach-Object | Set-Content` của
PowerShell để comment từng dòng — PowerShell 5.1 đã đọc/ghi lại file với codepage ANSI mặc định, làm hỏng
toàn bộ dấu tiếng Việt trong file (mojibake, VD "Đồng bộ" → "?ng b?"). Phát hiện ngay qua cảnh báo "file
changed on disk", **không chạy file bị hỏng**. Khắc phục: ghi lại toàn bộ file bằng nội dung UTF-8 đúng đã
có sẵn trong context (từ lần đọc trước đó), sau đó archive lại bằng script Node.js đọc/ghi tường minh
`utf8` (không qua PowerShell text pipeline) — verify lại bằng `grep` không còn ký tự lỗi. Bài học: **không
dùng PowerShell `Get-Content`/`Set-Content` để sửa file chứa tiếng Việt** — dùng Node.js hoặc Write tool
đọc/ghi UTF-8 tường minh thay thế.
