# DEV-007 — Domain Upload: khắc phục chuỗi IDOR (IMP-007→010)

> Ngày: 2026-09-01. Status: **DONE**. 4 sub-item: IMP-007 (MIME whitelist), IMP-008 (uploadedBy), IMP-009 (list scope+pagination), IMP-010 (ownership check detail/delete).

## Objective

Domain Upload (`POST/GET /api/upload`, `GET/DELETE /api/upload/:id`) có chuỗi lỗ hổng liên kết: không giới hạn loại file (IMP-007) → file không có chủ (IMP-008) → danh sách trả toàn bộ file mọi user (IMP-009) → không kiểm tra quyền sở hữu khi xem/xoá (IMP-010, IDOR đầy đủ).

## Quyết định nghiệp vụ (đã xác nhận với user trước khi code)

1. **IMP-007 — MIME whitelist**: `application/pdf`, `image/jpeg`, `image/png`, `.docx` (`application/vnd.openxmlformats-officedocument.wordprocessingml.document`), `.xlsx` (`application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`).
2. **IMP-009 — List scope**: user thường chỉ thấy file MÌNH upload (`uploadedBy`); ADMIN xem được tất cả (đồng bộ pattern ADMIN-bypass đã dùng xuyên suốt codebase — `isSystemRole===true || role.name==="ADMIN"`).

## Root Cause / Evidence (source hiện tại, trước fix)

- **IMP-007** (`H-09a`=`SEC-30`=`RV09-01`): `backend/src/services/upload/upload.middleware.ts:39` — `fileFilter`: `if (!options?.allowedTypes) return cb(null, true);`. `upload.routes.ts:14` gọi `createUploader()` KHÔNG tham số → nhận MỌI mime-type. (Đối chiếu `medicalDevice.routes.ts:40-43` đã dùng đúng pattern `createUploader({allowedTypes:[...]})` cho 1 domain khác — hạ tầng có sẵn, chỉ chưa dùng ở đây.)
- **IMP-008** (`H-09b`=`SEC-31`=`RV09-02`): `upload.service.ts:saveFilesToDB()` — không nhận/gán `uploadedBy` dù `upload.model.ts:16-19` đã có sẵn field này trong schema. File "vô chủ" là tiền đề trực tiếp khiến IMP-009/010 không thể implement (không có chủ sở hữu thì không check ownership được).
- **IMP-009** (`H-09c`=`SEC-32`=`RV09-03`): `upload.controller.ts:getFiles()` — `Upload.find({isDeleted:false})`, không filter theo `uploadedBy`, không phân trang.
- **IMP-010** (`H-09d`=`SEC-33`=`RV09-04`): `getFileDetail`/`deleteFile` — `Upload.findById(req.params.id)`, không so `uploadedBy` với `req.user`, không check role → bất kỳ user có permission `VIEW_FILE_DETAIL`/`DELETE_FILE` (dù chỉ 1 role sở hữu theo seed data hiện tại) xem/xoá được file của BẤT KỲ ai khác.

## Attack/Bug Flow (trước fix)

```
User A (có UPLOAD_FILES) upload 1 file → không giới hạn type → lưu, không có chủ (uploadedBy=null)
User B (có VIEW_FILES) GET /api/upload → thấy TOÀN BỘ file, kể cả của User A
User B GET /api/upload/:id (id của User A) → 200, xem được nội dung/link file
User B DELETE /api/upload/:id (id của User A) → 200, xoá được file của User A
```

## Affected Files

- `backend/src/routes/upload/upload.routes.ts` — `createUploader({allowedTypes:[...]})`.
- `backend/src/services/upload/upload.service.ts` — `saveFilesToDB(files, userId)` gán `uploadedBy`.
- `backend/src/controllers/upload/upload.controller.ts` — `uploadFiles` truyền `userId`; `getFiles` filter theo `uploadedBy` (trừ ADMIN) + phân trang; `getFileDetail`/`deleteFile` thêm guard ownership/ADMIN.
- `backend/src/docs/openAPI.yaml` — cập nhật 4 endpoint Upload (mô tả, response `403`/pagination), xoá ghi chú lỗi thời về permission "chưa thấy trong permission.constant.ts" (đã xác minh qua source — permission strings THỰC SỰ có trong `permission.constant.ts`, ghi chú cũ là OUTDATED so với source hiện tại).

**API Impact**:
- `POST /api/upload` — file sai mime-type nay bị từ chối (lỗi rơi vào nhánh `500` sẵn có, module chưa dùng `ApiError` chuẩn hoá — KHÔNG sửa ở task này, xem Remaining Issues).
- `GET /api/upload` — **breaking change response shape**: từ mảng phẳng `[...]` sang `{data:[...], pagination:{...}}`; nội dung cũng đổi (chỉ file của mình thay vì tất cả, trừ ADMIN).
- `GET/DELETE /api/upload/:id` — thêm case `403` mới khi không phải chủ file/ADMIN.

**Database Impact**: Không đổi schema (`uploadedBy` đã có sẵn). Không ghi dữ liệu migration cho file đã upload TRƯỚC fix này — các file cũ vẫn `uploadedBy: null/undefined`, xem Remaining Issues.

**RBAC Impact**: Không đổi permission nào (`UPLOAD_FILES`/`VIEW_FILES`/`VIEW_FILE_DETAIL`/`DELETE_FILE` giữ nguyên) — chỉ thêm business guard ở tầng controller.
