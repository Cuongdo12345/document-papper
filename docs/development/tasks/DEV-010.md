# DEV-010 — Asset business-logic bypass fixes (whitelist + regex escape)

> Ngày: 2026-09-01. Status: **DONE**. Gồm 2 sub-item độc lập: IMP-014 (Asset `isActive` whitelist bypass) + IMP-015 (escape regex 3 domain).

## Objective

- **IMP-014** (`H-07`=`SEC-35`=`RV06-01`): loại `isActive` khỏi `ASSET_UPDATE_WHITELIST` — trước đây user chỉ cần `ASSET_UPDATE` (không cần `ASSET_DELETE`) là soft-delete được Asset qua `PUT/PATCH /assets/:id`, bỏ qua guard nghiệp vụ + audit trail của `deleteAssetService()`.
- **IMP-015** (`H-08`=`SEC-36`=`RV06-02`): escape regex ở 3 domain Departments/RBAC/Assets — `$regex` nhận thẳng `keyword` từ client không qua `escapeRegex` (đã có sẵn, chỉ Documents dùng) → rủi ro ReDoS / lỗi regex khi keyword chứa ký tự đặc biệt (`.`, `*`, `+`, `(`, …).

## Evidence

**IMP-014**: `backend/src/services/assets/assetDevice/asset.service.ts:updateAssetService()` — `pickWhitelisted(payload, ASSET_UPDATE_WHITELIST)`, whitelist (trước fix) có `isActive`. Đối chiếu `deleteAssetService()` cùng file: có guard chặn xoá asset `status IN_USE/UNDER_MAINTENANCE` + ghi `deletedAt`/`deletedBy` — `updateAssetService` KHÔNG có 2 điều này, nên set `isActive:false` qua update bỏ qua HOÀN TOÀN cả 2. `assets.dto.ts:UpdateAssetDTO` (lớp Zod) cũng có `isActive` — cần bỏ cả 2 lớp (đúng pattern phòng thủ 2 lớp đã ghi trong comment file).

**IMP-015**: `backend/src/services/documents/documents.mapper.ts:escapeRegex()` (trước fix) — hàm đã có sẵn, chỉ `document.service.ts` dùng. `grep -rn "\$regex"` xác nhận unescaped tại: `departments.service.ts` (4 chỗ), `rbac.service.ts` (3 chỗ: Permission/Role/Policy search), `asset.service.ts`/`assetExcel.service.ts`/`assetCategory.service.ts` (Assets domain, 3 file × 2-3 chỗ).

## Implementation

**IMP-014**:
```diff
 export const ASSET_UPDATE_WHITELIST = [
   "category", "name", "serialNumber", "model", "manufacturer",
   "location", "purchaseDate", "purchasePrice", "warrantyExpiredAt",
   "supplier", "specs",
-  "isActive",
 ] as const;
```
(tương tự bỏ khỏi `UpdateAssetDTO`)

**IMP-015** (pattern lặp lại 9 vị trí, ví dụ `departments.service.ts`):
```diff
+import { escapeRegex } from "../../shared/utils/regex.util";
 ...
 if (keyword) {
+  const safeKeyword = escapeRegex(keyword);
   filter.$or = [
-    { code: { $regex: keyword, $options: "i" } },
-    { name: { $regex: keyword, $options: "i" } },
+    { code: { $regex: safeKeyword, $options: "i" } },
+    { name: { $regex: safeKeyword, $options: "i" } },
   ];
 }
```

**API Impact**:
- IMP-014: `PUT/PATCH /api/assets/:id` — field `isActive` trong request body giờ bị bỏ qua âm thầm (không throw — cùng hành vi `pickWhitelisted`/Zod strip field lạ hiện có cho field ngoài whitelist khác). Muốn soft-delete/khôi phục Asset phải dùng đúng endpoint xoá/khôi phục.
- IMP-015: Không đổi request/response shape/status code nào — chỉ đổi cách xử lý nội bộ giá trị `keyword`/`code`/`name` trước khi đưa vào Mongo. Kết quả tìm kiếm với keyword thông thường (không chứa ký tự regex đặc biệt) không đổi.

**Database Impact**: Không đổi schema, không ghi dữ liệu.

**RBAC Impact**: Không đổi permission nào.
