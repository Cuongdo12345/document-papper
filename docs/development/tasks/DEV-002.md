# DEV-002 — Safeguard ADMIN cho `resetPassword()`

> Ngày: 2026-08-31. Status: **DONE**. Không mở rộng sang DEV-003.

## Objective

Đóng `IMP-002`/`SEC-29`/`RV03-01`: `resetPassword()` (admin reset hộ mật khẩu user khác) thiếu guard chặn reset mật khẩu của tài khoản ADMIN, dù chính docstring của hàm mô tả hành vi này.

## Evidence

`backend/src/services/users/users.service.ts:resetPassword()` — docstring (dòng ~374-382, dùng chung comment block với `disable()`) liệt kê rõ: *"Nếu role là ADMIN => không cho reset password"* / *"Nếu cố gắng reset password của ADMIN => 400"*. Code thân hàm (trước fix) chỉ kiểm tra `user` tồn tại + `isActive`, **không hề query `Role` hay so sánh gì cả** — khác hẳn `disable()` cùng file đã có guard tương ứng.

## Root Cause

Thiếu sót triển khai (docstring viết trước, code chưa từng implement đúng phần "chặn ADMIN"). Route `PATCH /reset-password/:id` (`user.routes.ts:106-110`) chỉ có `authenticate` + `authorizePermission("USER_RESET_PASSWORD")` — không có business guard nào khác ở controller (`resetPasswordByAdmin`, `user.controller.ts:101-107`) hay service. Nếu `USER_RESET_PASSWORD` từng được cấp cho role không phải ADMIN (dữ liệu RBAC thật UNKNOWN), đây là đường account-takeover ADMIN hoàn chỉnh: đặt lại mật khẩu ADMIN rồi đăng nhập bằng mật khẩu mới.

## Scope

Chỉ `resetPassword()` (admin reset hộ). Không đụng `changePassword()` (tự đổi mật khẩu, có check mật khẩu cũ, không liên quan finding này) hay flow `resetPassword` trong `auths.service.ts` (self-service qua token, không phải admin-triggered — tên hàm trùng nhưng khác domain/file, đã xác nhận qua route/import, không sửa).

## Affected Files

- `backend/src/services/users/users.service.ts` (duy nhất file sửa)
- `backend/src/services/users/__tests__/users.service.test.ts` (mới — test)

## Implementation

Thêm guard NGAY SAU check `isActive`, TRƯỚC khi hash/lưu password mới — cùng pattern OR đã dùng ở DEV-001A cho `disable()`/`assignRole()`/`create()`/`update()` cùng file (ưu tiên `Role.isSystemRole`, giữ literal `"ADMIN"` làm lưới đỡ Phase A, tránh lockout nếu migration `isSystemRole` chưa chạy):

```ts
const targetRole = await Role.findById(user.role).select("name isSystemRole");
if (targetRole?.isSystemRole === true || targetRole?.name === "ADMIN") {
  throw ApiError.badRequest("Không thể reset mật khẩu tài khoản ADMIN");
}
```

**API Impact**: `PATCH /api/users/reset-password/:id` — thêm 1 rejection case mới (`400`) khi target là ADMIN. Không đổi request/response shape hiện có cho case còn lại.

**Database Impact**: Thêm 1 query đọc (`Role.findById`) trước khi ghi — không có write mới, không đổi schema.

**RBAC Impact**: Không đổi permission nào (`USER_RESET_PASSWORD` giữ nguyên) — chỉ thêm business guard ở tầng service, nhất quán với các guard ADMIN khác cùng file.
