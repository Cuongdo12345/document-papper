# DEV-014 — Auth Hardening Lớp 2 (refresh token hash, jwt.verify try/catch, CORS fail-fast)

> Ngày: 2026-09-01. Status: **DONE**. IMP-020 = MEDIUM-05 + MEDIUM-06 + MEDIUM-09.

## Objective

3 vấn đề cùng nhóm "Auth hardening lớp 2" theo roadmap, gộp 1 task (cùng domain Authentication, độc lập nhau về code):
1. Refresh token lưu plaintext trong DB.
2. `refresh()` không bọc `jwt.verify()` trong try/catch → lỗi 500 rò rỉ message thư viện.
3. CORS fallback mở `*` khi thiếu `CLIENT_URL`.

## Root Cause / Evidence (đã verify lại trên source hiện tại)

- `backend/src/models/auth/refreshToken.model.ts` — `token: { type: String, required: true }`, không hash, khác hẳn `PasswordResetToken` (đã hash SHA-256 qua `hashResetToken`).
- `backend/src/services/auth/auths.service.ts:login()` — `RefreshToken.create({ token: refreshToken, ... })` lưu thẳng JWT raw.
- `backend/src/services/auth/auths.service.ts:refresh()` — `jwt.verify(refreshToken, ...)` gọi trực tiếp, KHÔNG bọc try/catch. Xác nhận `errorHandler` (`error.middleware.ts`) không có nhánh riêng cho `JsonWebTokenError`/`TokenExpiredError` — lỗi rơi vào nhánh fallback cuối: `status = getSafeStatus(err)` (mặc định 500 vì lỗi JWT không có field `status`), `message: err.message` (message thư viện gốc, VD "jwt expired").
- `backend/src/app.ts:54-61` — `cors({ origin: process.env.CLIENT_URL, credentials: true, ... })`. Theo hành vi thư viện `cors`: nếu `origin` là `undefined` (biến ENV không set), thư viện coi như KHÔNG cấu hình `origin`, mặc định fallback `Access-Control-Allow-Origin: *` — kết hợp `credentials:true` là fail-OPEN.
- `backend/server.ts:15-23` — đã có sẵn pattern fail-fast cho `PORT`/`MONGO_URI` (`if (!process.env.X) throw new Error(...)`) ngay lúc khởi động, TRƯỚC KHI `app.ts` được import/chạy — nhưng KHÔNG có check tương tự cho `CLIENT_URL`.

## Changes

### 1. MEDIUM-05 — Hash refresh token

- `backend/src/shared/helpers/auth.helper.ts` — cập nhật doc-comment của `hashResetToken()` (không đổi implementation) để phản ánh việc dùng lại cho refresh token, không chỉ reset password. Không đổi tên hàm (tránh rename lan sang nhiều chỗ ngoài scope không cần thiết) — hàm vốn đã generic (SHA-256 hash 1 chuỗi bất kỳ).
- `auths.service.ts:login()` — `RefreshToken.create({ token: hashResetToken(refreshToken), ... })`. Client vẫn nhận `refreshToken` RAW trong response (không đổi API contract).
- `auths.service.ts:refresh()` — `RefreshToken.findOne({ token: hashResetToken(refreshToken), ... })`.
- `auths.service.ts:logout()` — `RefreshToken.findOneAndUpdate({ token: hashResetToken(refreshToken), user: userId }, ...)`.

### 2. MEDIUM-06 — Bọc `jwt.verify()` trong try/catch

- `auths.service.ts:refresh()` — bọc `jwt.verify(...)` trong try/catch, map mọi lỗi (hết hạn, sai chữ ký, sai format) về `ApiError.unauthorized("Refresh token không hợp lệ hoặc đã hết hạn")` — nhất quán 401 thay vì 500, không còn lộ message thư viện gốc.

### 3. MEDIUM-09 — CORS fail-fast khi thiếu `CLIENT_URL`

- `backend/server.ts` — thêm `if (!process.env.CLIENT_URL) throw new Error(...)` ngay sau check `MONGO_URI`, cùng pattern/vị trí với `PORT`/`MONGO_URI` đã có.
- KHÔNG sửa `app.ts` — cấu hình `cors({origin: process.env.CLIENT_URL, ...})` giữ nguyên, vì fail-fast ở `server.ts` đảm bảo `app.ts` không bao giờ chạy được với `CLIENT_URL` rỗng/undefined.

## API Impact

- `POST /api/auths/login`: KHÔNG đổi contract (response shape/status giữ nguyên) — chỉ đổi cách lưu nội bộ.
- `POST /api/auths/refresh`: token hết hạn/hỏng giờ trả `401` (`ApiError.unauthorized`) thay vì `500` với message thư viện gốc — thay đổi có chủ đích, breaking nhẹ (status code khác) nhưng đúng hướng (401 semantically đúng hơn 500 cho lỗi xác thực).
- `POST /api/auths/logout`: KHÔNG đổi contract.
- Khởi động server (`npm run start`/`npm run dev`): **BREAKING nếu thiếu `CLIENT_URL` trong ENV** — server giờ crash ngay lúc khởi động thay vì chạy với CORS mở `*`. `.env` dev hiện ĐÃ có `CLIENT_URL=http://localhost:3000` — xác nhận không phá vỡ dev hiện tại. **Cần xác nhận production ENV cũng đã set `CLIENT_URL` trước khi deploy** (UNKNOWN, ngoài khả năng truy cập của tôi — xem Remaining Issues).

## Database Impact

- **Migration/backward-compat quan trọng**: mọi `RefreshToken` đã tồn tại trong DB TRƯỚC khi deploy fix này lưu **plaintext**. Sau khi deploy, `refresh()`/`logout()` hash token đến trước khi so khớp — các token cũ (plaintext trong DB) sẽ KHÔNG còn khớp được (so sánh hash-của-raw-token với plaintext-đã-lưu luôn `false`). **Hệ quả: mọi user đang đăng nhập tại thời điểm deploy sẽ bị "refresh() thất bại" ở lần gọi tiếp theo, buộc phải đăng nhập lại.** Đây là hệ quả 1 lần, chấp nhận được cho 1 fix bảo mật (đúng roadmap khuyến nghị), nhưng cần LƯU Ý khi deploy — không phải lỗi, là tác dụng phụ đã biết trước.
- Không cần migration script (không cần chuyển đổi dữ liệu cũ — token cũ chỉ đơn giản ngừng hoạt động, không gây lỗi/crash, chỉ 401 khi refresh).

## RBAC/Security Impact

- Đóng đúng 3 finding MEDIUM-05/06/09.
- MEDIUM-05: giảm impact nếu DB bị lộ (backup/injection/insider) — attacker có hash, không dùng được ngay như plaintext.
- MEDIUM-06: đóng lỗ hổng rò rỉ thông tin lỗi (error leakage), chuẩn hoá status code.
- MEDIUM-09: đảm bảo CORS không bao giờ fail-open do thiếu ENV.
