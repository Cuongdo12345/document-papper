## 3. File mới — `backend/src/services/systemDesign/moduleDescriptions.ts`

```ts
export interface ModuleDescription { description: string; features: string[] }
export const MODULE_DESCRIPTIONS: Record<string, ModuleDescription> = { apiPerformance: {...}, assets: {...}, ... };
```

Key = ĐÚNG tên thư mục domain thật (khớp `module.name` suy ra ở `systemDesign.service.ts`) — không suy đoán
tên khác. Module không có entry vẫn hoạt động bình thường (`description`/`features` optional ở
`SystemDesignModule`, response chỉ thiếu 2 field này, không lỗi) — đây là lý do CLAUDE.md §36 bước 9 mới chỉ
"khuyến nghị mạnh", không phải ràng buộc cứng gây crash nếu quên.

## 4. File mới — `backend/src/services/systemDesign/relatedDocs.ts`

`buildRelatedDocsMap(moduleNames: string[]): Map<string, RelatedDoc[]>`:

- **Tìm repo root**: đi lên từ `__dirname` tới khi thấy `docs/development/tasks` tồn tại — KHÔNG hard-code
  số cấp `"../../.."` cố định, vì độ sâu `__dirname` khác nhau giữa dev (`ts-node`, chạy trực tiếp
  `backend/src/services/systemDesign`) và prod (`node dist/...`, chạy từ `backend/dist/src/services/systemDesign`
  — thêm 1 cấp `dist/`). Cách đi-lên-tới-khi-thấy-marker này đúng ở cả 2 môi trường mà không cần biết trước
  cấu trúc build — pattern `MODELS_ROOT` cũ ở `systemDesign.service.ts` dùng `"../../models"` cố định vẫn
  đúng chỉ vì `docs/` không nằm trong `backend/`, còn `models/` thì có (nên độ sâu tương đối từ `src`/`dist/src`
  tới `models` giống nhau — KHÔNG áp dụng được cùng pattern cho `docs/`, đây là lý do phải viết hàm riêng
  thay vì tái dùng `MODELS_ROOT`).
- Đọc TOÀN BỘ `.md` trong 2 thư mục task 1 lần (`readAllTaskFiles`), rồi với MỖI module kiểm tra substring
  `models/<module>/` hoặc `features/<module>/` có xuất hiện trong nội dung file hay không — ĐÚNG yêu cầu
  gốc, không phân biệt module có thư mục FE tương ứng hay không (nếu backend module không có FE feature
  cùng tên — vd `apiPerformance`, `importAudit`, `uploadFiles` — pattern `features/<module>/` đơn giản
  không match được file nào, đó là kết quả ĐÚNG chứ không phải lỗi).
- URL: `https://github.com/Cuongdo12345/document-papper/blob/main/<repo-relative-path>`.
- **[CẬP NHẬT 2026-09-30, DEV-107/BR-21] Mục này đã LỖI THỜI: kết quả quét nay được cache 60 giây.** Nội dung gốc: KHÔNG cache — chạy lại mỗi lần gọi API (đúng yêu cầu "không cần cache phức tạp ở bản đầu"); đọc file ở
  local disk trong process backend nên chi phí không đáng kể (không phải network call).

## 5. Tích hợp vào `systemDesign.service.ts`

`getSystemDesignService()` — sau khi build xong `modulesMap`, gọi `buildRelatedDocsMap(moduleNames)` 1 lần
(không gọi lại trong loop), rồi map mỗi module: `{ name, models, ...MODULE_DESCRIPTIONS[name], relatedDocs:
relatedDocsMap.get(name) ?? [] }` — spread `MODULE_DESCRIPTIONS[name]` (có thể `undefined`) an toàn vì spread
`undefined` là no-op trong JS/TS (không throw).

`SystemDesignModule` interface thêm `description?`, `features?` (optional — đúng lý do ở Mục 3), `relatedDocs`
(bắt buộc, luôn là mảng).
