# DEV-096 — BR-08: cấu hình `trust proxy` qua ENV `TRUST_PROXY`

**Ngày:** 2026-09-29
**Trạng thái:** DONE
**Loại:** SECURITY, CONFIGURATION

**Nguồn:** `docs/31_BACKEND_CODE_REVIEW.md` BR-08 (MEDIUM).

## 1. Hiện trạng trước khi sửa

- `app.ts` không có `app.set("trust proxy", ...)`. Stack: Express 5.2.1, express-rate-limit 8.3.2.
- `req.ip` đang được dùng ở 2 nơi:
  - `authRateLimiter` (100 lần / 15 phút, đếm theo IP) trên `/login`, `/login/verify-otp`, `/refresh-token`, `/reset-password`, `/2fa/*`, `/register`.
  - IP lưu trong `RefreshToken.ip` và hiển thị ở "Phiên đăng nhập" (DEV-069).
- Kế hoạch deploy (`PRODUCTION_DEPLOYMENT_PLAN.md`) là Trình duyệt → Cloudflare → Nginx → Node. Khi chạy sau proxy, `req.ip` sẽ là IP của Nginx, nên:
  - Tất cả người dùng chung một bộ đếm rate limit: đủ người đăng nhập là ai cũng bị 429.
  - IP ở "Phiên đăng nhập" sai.

## 2. Quyết định của user (AskUserQuestion)

**ENV `TRUST_PROXY`, mặc định tắt.** Không cố định 2 lớp trong code, và không cố định 1 lớp (Nginx real_ip).

## 3. Thay đổi

- **Mới** `backend/src/shared/utils/trustProxy.util.ts::parseTrustProxy(raw)`:
  - Bỏ trống, `0` hoặc `false` → `false` (tắt; dev chạy trực tiếp như cũ).
  - Số nguyên N ≥ 1 → N lớp proxy.
  - `true` hoặc giá trị khác (`-1`, `1.5`, `loopback`…) → **throw lúc khởi động** (fail-fast, cùng tinh thần các kiểm tra ENV ở `server.ts`). `true` tin mọi hop, nên client tự gửi `X-Forwarded-For` giả là lách được rate limit.
  - Danh sách IP/subnet (Express có hỗ trợ) chưa cần; thêm khi có nhu cầu.
- `backend/src/app.ts`: `app.set("trust proxy", parseTrustProxy(process.env.TRUST_PROXY))`, đặt ngay sau `express()`, trước mọi middleware.
- `backend/.env.example`: thêm `TRUST_PROXY=` kèm giải thích; production đặt `2`.
- `backend/src/models/auth/refreshToken.model.ts`: cập nhật comment cũ ("ngoài phạm vi task này") để trỏ tới cấu hình mới.
- `docs/development/PRODUCTION_DEPLOYMENT_PLAN.md` Giai đoạn 1: thêm bước bắt buộc
  - đặt `TRUST_PROXY=2`;
  - Nginx cấu hình `proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;`;
  - cách kiểm tra IP thật sau khi deploy.

**Không đổi:** `.env` dev (không có biến này nên vẫn tắt), logic rate limit, API, frontend.

## 4. Test

- Unit mới `shared/utils/__tests__/trustProxy.util.test.ts` (15 test):
  - Các giá trị tắt: `undefined`, `""`, khoảng trắng, `0`, `false`, `FALSE`.
  - Số lớp: `1`, `2`, `" 2 "`.
  - Throw: `true`, `TRUE`, `-1`, `1.5`, `abc`, `loopback`.
- E2E mới `__tests__/e2e/trust-proxy.e2e-test.ts` (4 test, `TRUST_PROXY=1`; supertest đóng vai 1 lớp proxy gửi `X-Forwarded-For`):
  - `app.get("trust proxy") === 1`.
  - IP ở "Phiên đăng nhập" là IP người dùng trong `X-Forwarded-For`.
  - Client chèn IP giả ở đầu header (`"1.1.1.1, 198.51.100.9"`): hệ thống vẫn ghi `198.51.100.9`, không giả được.
  - Rate limit đếm riêng theo IP người dùng: cùng IP thì `RateLimit-Remaining` giảm dần, IP khác có bộ đếm riêng.
- Trạng thái mặc định (tắt) được kiểm bằng unit test và bởi mọi file E2E khác, vốn không đặt biến này.
- Backend: jest 49 suites / 503 tests PASS; e2e 16 suites / 101 tests PASS; `npm run build` PASS.

## 5. Việc cần làm khi deploy (chưa làm được ở dev)

Kiểm tra thật trên hạ tầng Cloudflare + Nginx theo bước đã ghi trong `PRODUCTION_DEPLOYMENT_PLAN.md`. Dev hiện không có proxy nên chưa có cách kiểm tra thực tế.
