# DEV-018 — Performance: Index WorkflowInstance/Document/Asset + Sửa Metric Endpoint Sai

> Ngày: 2026-09-02. Status: **DONE**. IMP-024 (ISS-05/RV05-08 + PERF-03/RV07-02), IMP-025 (RV11-02).

## Objective

1. (IMP-024) Thêm index còn thiếu cho 3 model đang bị COLLSCAN ở các truy vấn tần suất cao/dashboard: `WorkflowInstance` (hộp thư chờ duyệt), `Document` + `Asset` (dashboard lọc `isActive`/`deletedAt`).
2. (IMP-025) Sửa bug TÍNH ĐÚNG của chính dashboard hiệu năng: `endpoint` ghi thiếu `req.baseUrl`, gộp lẫn nhiều domain khác nhau vào cùng 1 nhóm thống kê.

## Root Cause / Evidence (verify lại trên source hiện tại)

### IMP-024a — `WorkflowInstance` không có index nào ngoài `_id`

- `backend/src/models/documents/workflowInstance.model.ts` — trước fix: schema không gọi `.index()` lần nào.
- `backend/src/services/documents/workflow.service.ts:getPendingApprovalsForRole()` (endpoint "hộp thư chờ duyệt", tần suất cao — mọi approver gọi thường xuyên để biết việc đang chờ mình) filter `{status:"pending", $expr:{...steps[currentStep].role...}}`, sort `{createdAt:1}` — COLLSCAN toàn bộ collection mỗi lần gọi.
- `$expr`/mảng lồng động (`steps.role` theo `currentStep`) không thể index trực tiếp — đúng như ghi nhận gốc (REF-007/ISS-05: khuyến nghị tối thiểu `{status:1}`).

### IMP-024b — `Document`/`Asset` thiếu index cho `isActive`/`deletedAt`

- `backend/src/services/dashboard/dashboard.service.ts` — xác nhận lại: 8+ vị trí `$match`/`find()` lọc `{isActive:true, deletedAt:null}` (dòng 111, 129-132, 143-146, 156, 178, 225, 243-247, 258-262, 271, 310, 371-375, 441-442, 522-526).
- `backend/src/services/dashboard/assetDashboard.service.ts` — dòng 19, 129, 173: `$match:{isActive:true}`.
- `backend/src/models/documents/document.model.ts` — trước fix: có nhiều index (`documentCode`, `title text`, `subType+department`, `referenceTo`, `department+subType+createdAt`, `createdBy`, `createdAt`, `referenceTo+category+isActive+createdAt`) nhưng KHÔNG index nào có `isActive`/`deletedAt` làm field ĐẦU (chỉ 1 compound có `isActive` ở giữa, không giúp query chỉ lọc `isActive+deletedAt`).
- `backend/src/models/assets/asset.model.ts` — trước fix: chỉ có `{department,status}`, `{category,status}`, `{assignedTo}`, text index — hoàn toàn không có `isActive`/`deletedAt`.

### IMP-025 — `endpoint` ghi thiếu `req.baseUrl`

- `backend/src/middlewares/performance.middleware.ts:131` (trước fix): `endpoint: req.route?.path || req.originalUrl`.
- `req.route.path` là hành vi CHUẨN của Express — CHỈ là phần path tương đối trong router con đang xử lý request (VD `"/:id"`), KHÔNG bao gồm tiền tố mount (`req.baseUrl`, VD `"/api/documents"`).
- `backend/src/controllers/performances/performance.controller.ts:177` group theo `endpoint` này (`$group:{_id:"$endpoint", endpoint:"$_id",...}`) — vì hàng chục router con dùng chung các pattern phổ biến (`"/:id"`, `"/"`, `"/:id/read"`...), số liệu của nhiều domain khác nhau (Document, Asset, User, Department...) bị GỘP LẪN vào cùng 1 nhóm thống kê, hỏng đúng mục đích cốt lõi của dashboard hiệu năng (biết endpoint NÀO thật sự chậm).

## Changes

### 1. `models/documents/workflowInstance.model.ts` — thêm index

```ts
workflowInstanceSchema.index({ status: 1, createdAt: 1 });
```

Ghép thêm `createdAt` (khớp `sort({createdAt:1})` của đúng truy vấn `getPendingApprovalsForRole`) thay vì chỉ `{status:1}` như khuyến nghị tối thiểu gốc — để index phục vụ được cả `$match` VÀ `sort` cùng lúc (tránh bước `SORT` riêng sau `IXSCAN`), không đổi phạm vi finding (vẫn cùng 1 index, cùng field `status` được khuyến nghị).

### 2. `models/documents/document.model.ts` — thêm index

```ts
DocumentSchema.index({ isActive: 1, deletedAt: 1, createdAt: -1 });
```

Đúng shape đã đề xuất ở TD-22/REF-021 (`{isActive:1, deletedAt:1, createdAt:-1}`).

### 3. `models/assets/asset.model.ts` — thêm index

```ts
AssetSchema.index({ isActive: 1, deletedAt: 1, createdAt: -1 });
```

Cùng shape với Document, đúng mở rộng phạm vi RV07-02.

### 4. `middlewares/performance.middleware.ts` — sửa cách ghi `endpoint`

```ts
endpoint: req.route?.path
  ? `${req.baseUrl}${req.route.path}`
  : req.originalUrl,
```

Khi route khớp: ghép `req.baseUrl` + `req.route.path` (VD `"/api/documents" + "/:id"` = `"/api/documents/:id"`). Khi route KHÔNG khớp (VD 404, `req.route` undefined): giữ fallback `req.originalUrl` như cũ.

## API Impact

Không đổi API nghiệp vụ nào. `GET /api/performances` (dashboard hiệu năng) sẽ trả `endpoint` CHI TIẾT HƠN/ĐÚNG HƠN sau fix (VD trước: nhiều domain gộp chung `"/:id"`; sau: `"/api/documents/:id"`, `"/api/assets/:id"` tách riêng) — đây là thay đổi CÓ CHỦ ĐÍCH, đúng hướng, nhưng **dữ liệu `ApiPerformance` cũ (ghi TRƯỚC deploy)** vẫn giữ format `endpoint` cũ (không có `baseUrl`) — nghĩa là sau deploy, thống kê sẽ có 1 giai đoạn dữ liệu cũ/mới lẫn lộn format cho tới khi TTL 30 ngày tự dọn hết bản ghi cũ. Không có script migrate ngược cho dữ liệu cũ (ngoài phạm vi task — dữ liệu hiệu năng có TTL, giá trị giảm nhanh theo thời gian, không cần migrate).

## Database Impact

- 4 index mới, KHÔNG đổi field/type/relationship/dữ liệu hiện có nào — an toàn tuyệt đối về mặt tương thích ngược.
- Nếu Mongoose `autoIndex: true` (thường bật ở dev): index tạo ngay khi app khởi động. Production nên build index qua migration/`mongosh` có kiểm soát thời điểm (tránh build index lúc peak traffic trên collection lớn — `createIndex` mặc định block collection ở MongoDB cũ, hoặc tốn CPU/IO đáng kể ở bản mới dù không block).
- Nên chạy `explain("executionStats")` sau deploy trên `getPendingApprovalsForRole` và 1-2 aggregate dashboard để xác nhận `IXSCAN` thay vì `COLLSCAN` như khuyến nghị gốc — **CHƯA làm được trong task này** (cần môi trường có dữ liệu đủ lớn để thấy khác biệt rõ, và cần chạy `mongosh`/kết nối DB thật).
