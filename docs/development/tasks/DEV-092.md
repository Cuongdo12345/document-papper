# DEV-092 — BR-03: tạo tài liệu không còn tin `department` do client gửi lên

**Ngày:** 2026-09-29
**Trạng thái:** DONE
**Loại:** SECURITY, RBAC, API CHANGE

**Nguồn:** `docs/31_BACKEND_CODE_REVIEW.md` BR-03 (HIGH).

## 1. Hiện trạng trước khi sửa

- `POST /api/documents/proposal` chỉ yêu cầu `DOCUMENT_CREATE`. `createDocumentService` dùng nguyên `department` trong body. Gọi API trực tiếp là tạo được tài liệu vào khoa bất kỳ, và thông báo `DOCUMENT_SUBMITTED` gửi tới toàn bộ khoa đó.
- Frontend khoá ô khoa theo `DEPARTMENT_VIEW`, nhưng backend không kiểm tra lại. Trong khi đó, sửa tài liệu (`isSameDepartment`) và xem danh sách (`applyDepartmentFilter`) đều đã giới hạn theo khoa.
- **Lỗi phụ phát hiện thêm:** controller viết `{ userId: req.user._id, ...req.body }`, nên body có thể ghi đè `userId`, tức là giả mạo `createdBy`.
- **DB dev** (read-only):
  - Chỉ ADMIN và USER có `DOCUMENT_CREATE`. IT không còn quyền này trên DB, dù code map vẫn cấp.
  - `DEPARTMENT_VIEW` thuộc ADMIN, IT và PHONG_VAT_TU_TTB.
  - 73/278 tài liệu thuộc khoa khác khoa người tạo: 72 do ADMIN tạo, 1 do USER tạo. Không sửa dữ liệu cũ; tài liệu của USER có thể do người đó đã chuyển khoa.

## 2. Quyết định của user (AskUserQuestion)

Chọn **permission mới riêng `DOCUMENT_CREATE_ALL_DEPARTMENTS`**, không dùng "chỉ Admin" hay "Admin + DEPARTMENT_VIEW". Role nào cần quyền này thì gán qua UI "Phân quyền".

## 3. Thay đổi backend

- `shared/constants/permission.constant.ts`: thêm `DOCUMENT_CREATE_ALL_DEPARTMENTS`.
  - `rolePermission.map.ts`: ADMIN tự có qua `Object.values(PERMISSIONS)`. **Không** gán cho IT hay role khác trong code map.
- `services/documents/documents.scope.ts`: hàm mới `canCreateInDepartment(actor, department)` trả true khi `isAdmin`, hoặc `canCreateAllDepartments`, hoặc `isSameDepartment(department, callerDepartment)`.
  - Fail-closed: thiếu khoa thì trả false.
  - Cố ý không đọc `canViewAllDepartments`, vì quyền xem không kéo theo quyền tạo.
- `services/documents/documents.types.ts`: `CreateDocumentPayload` thêm `callerDepartment`, `isAdmin` và `canCreateAllDepartments`.
- `services/documents/document.service.ts::createDocumentService` (dòng 97): kiểm tra phạm vi khoa **đầu tiên**, trước mọi truy vấn. Vi phạm thì trả **403**. Thông báo lỗi tách riêng trường hợp user chưa thuộc khoa nào.
- `controllers/documents/document.controller.ts::createDocuments`:
  - Lấy permission qua `getCachedPermissions`, cùng pattern với `getAllDocuments`.
  - Đặt `userId`, `callerDepartment`, `isAdmin`, `canCreateAllDepartments` **sau** `...req.body`, nên body không ghi đè được. Cách này sửa luôn lỗi giả mạo `createdBy`.
- `docs/openAPI.yaml`: `/api/documents/proposal` thêm description và mô tả response 403.

**RBAC (CLAUDE.md §18):**
- Route vẫn yêu cầu `DOCUMENT_CREATE` (`authorizePermission`, `routes/documents/document.route.ts`).
- Quyền tạo cho khoa khác được kiểm tra ở `document.service.ts:97` bằng permission `DOCUMENT_CREATE_ALL_DEPARTMENTS`, đọc ở `document.controller.ts:37`.
- Đã xác nhận 401/403 thật bằng E2E (mục 5).

## 4. DB dev: seed permission

Làm theo pattern DEV-068/077/086. Script tạm `backend/scripts/_tmp-seed-br03.ts` (đã xoá sau khi chạy):
- Tạo `Permission` `DOCUMENT_CREATE_ALL_DEPARTMENTS` với resource `DOCUMENT`, action `CREATE_ALL_DEPARTMENTS`, mô tả "Tạo tài liệu cho khoa/phòng khác khoa của mình".
- Gán cho ADMIN qua `assignPermissionsToRoleService`, bằng danh sách hiện có cộng thêm quyền mới (có clear cache). ADMIN tăng từ 116 lên 117 permission.
- Chạy lại để kiểm tra: catalog đã có permission, ADMIN đã có.

**Chưa gán cho role nào khác.** User tự gán qua UI "Phân quyền" nếu cần, ví dụ cho IT tạo đề xuất sửa chữa cho khoa khác. Lưu ý IT trên DB hiện cũng không có `DOCUMENT_CREATE`.
