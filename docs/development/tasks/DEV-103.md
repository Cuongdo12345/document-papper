# DEV-103 — BR-15: giới hạn số file mỗi request upload

**Ngày:** 2026-09-30
**Trạng thái:** DONE
**Loại:** SECURITY, CONFIGURATION (full-stack, phần frontend ở `FE-41.md`)

**Nguồn:** `docs/31_BACKEND_CODE_REVIEW.md` BR-15 (LOW).

## 1. Hiện trạng trước khi sửa

`POST /api/upload` dùng `uploader.array("files")`, và `createUploader()` chỉ đặt `limits.fileSize` (10MB mỗi file). **Không giới hạn số file** mỗi request, nên một request có thể ghi vô số file lên đĩa (mỗi file ≤ 10MB). Thư mục `uploads/` là đĩa cục bộ của server.

BR-15 còn nêu: MIME type do client tự khai báo (không kiểm tra nội dung file).

## 2. Quyết định của user (AskUserQuestion)

- Giới hạn **10 file / request** (tối đa 100MB mỗi request).
- Kiểm tra nội dung file (magic bytes) **chỉ ghi nhận, chưa làm**.

## 3. Thay đổi

- `services/upload/upload.middleware.ts`:
  - hằng số `MAX_FILES_PER_REQUEST = 10`;
  - `createUploader` nhận thêm option `maxFiles` (mặc định 10) và đặt `limits.files`.
  - Vượt giới hạn → `MulterError LIMIT_FILE_COUNT` → 400 (`error.middleware.ts` đã có sẵn thông báo tiếng Việt, DEV-017). Multer tự xoá các file đã ghi dở của request đó.
- Route tải giấy chứng nhận kiểm định (`medicalDevice.routes.ts`, dùng chung `createUploader`) chỉ nhận 1 file nên không bị ảnh hưởng.
- Tài liệu: `openAPI.yaml` (`POST /api/upload`, đồng thời sửa mô tả cũ nói file sai loại rơi vào 500, thực tế là 400 từ DEV-017); `docs/frontend/API_REFERENCE.md`.
- Không có route/permission mới, không đổi model.

## 4. Test

- E2E mới `__tests__/e2e/upload-file-limit.e2e-test.ts` (5 test, multer ghi đĩa thật):
  - không token → 401;
  - đúng 10 file → 200, đủ 10 bản ghi;
  - 11 file → 400 `MULTER_LIMIT_FILE_COUNT`, **không bản ghi nào được lưu và không còn file dở trên đĩa**;
  - USER thiếu `UPLOAD_FILES` → 403 (route vẫn được bảo vệ, CLAUDE.md §18).
  - File test mang tiền tố `br15-e2e-`, được xoá trong `afterAll`. Đã kiểm tra thư mục `uploads/` sau khi chạy vẫn đúng 6 file ban đầu.
- **Đã kiểm chứng test bắt được lỗi:** tạm gỡ `limits.files` thì test 11 file fail (trả 200 thay vì 400); khôi phục thì pass.

## 5. Ngoài phạm vi (ghi nhận, chưa sửa)

- **Kiểm tra nội dung file (magic bytes):** `allowedTypes` so với `file.mimetype` do client khai báo. File không phải PDF/ảnh/Office vẫn qua được nếu khai báo mime hợp lệ. Giảm thiểu hiện có: file chỉ được trả về khi tải xuống, không được thực thi trên server. Cần làm riêng nếu muốn chặn (đọc đầu file sau khi lưu, xoá nếu sai; cân nhắc docx/xlsx thực chất là ZIP).
- Controller `uploadFiles` trả 200 (không phải 201) và vẫn tự bắt lỗi thành 500 chung: thuộc BR-22.
- Chưa giới hạn tổng dung lượng request, số field, số part ngoài `files` (multer mặc định).
