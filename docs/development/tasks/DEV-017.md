# DEV-017 — Nhận Diện Riêng Lỗi Multer Trong Error Handler

> Ngày: 2026-09-01. Status: **DONE**. IMP-023 = MEDIUM-13 (RV08-01).

## Objective

Lỗi Multer (sai định dạng/vượt kích thước file) trước đây rơi vào nhánh 500 "lỗi không xác định" chung của `error.middleware.ts` thay vì 400 rõ ràng — áp dụng cho mọi route dùng `uploadExcel` (Document import, Department sync, Asset import) và `createUploader()` (Upload module, Calibration certificate).

## Root Cause / Evidence (đã verify lại trên source hiện tại)

- `backend/src/middlewares/error.middleware.ts` — trước fix chỉ có nhánh `ApiError`/`CastError`/`ValidationError`/fallback 500, KHÔNG có nhánh nào cho lỗi Multer.
- Phát hiện **2 lớp lỗi khác nhau** cần xử lý riêng (chi tiết hơn evidence gốc RV08-01):
  1. **`MulterError` thật** (class riêng của thư viện `multer`, VD `code: "LIMIT_FILE_SIZE"`/`"LIMIT_FILE_COUNT"`/...) — do multer TỰ throw khi vượt `limits` đã cấu hình (`fileSize`, `files`...).
  2. **`Error` thường** — `backend/src/middlewares/upload.middleware.ts:fileFilter` (`uploadExcel`, dùng cho Document/Department/Asset import) và `backend/src/services/upload/upload.middleware.ts:createUploader().fileFilter` (Upload module + Calibration certificate) đều tự `cb(new Error(...))` khi sai định dạng/MIME type — đây là hành vi ĐÃ BIẾT của Multer: lỗi ném từ `fileFilter` KHÔNG được multer wrap lại thành `MulterError`, nên 1 nhánh `if (err instanceof MulterError)` đơn thuần sẽ KHÔNG bắt được trường hợp sai định dạng, chỉ bắt được trường hợp vượt kích thước/số lượng.
- Xác nhận cả 2 file trên KHÔNG dùng `ApiError` cho lỗi `fileFilter` (dùng `Error` thuần) — trong khi `error.middleware.ts` đã có nhánh xử lý `ApiError` đầy đủ (400 + message + errorCode) ngay từ đầu.

## Changes

### 1. `error.middleware.ts` — thêm nhánh `MulterError`

- Import `multer` (chỉ dùng class `MulterError`, không dùng gì khác).
- Thêm `MULTER_ERROR_MESSAGES` — map 8 `ErrorCode` của Multer (`LIMIT_PART_COUNT`/`LIMIT_FILE_SIZE`/`LIMIT_FILE_COUNT`/`LIMIT_FIELD_KEY`/`LIMIT_FIELD_VALUE`/`LIMIT_FIELD_COUNT`/`LIMIT_UNEXPECTED_FILE`/`MISSING_FIELD_NAME`) sang message tiếng Việt rõ nghĩa.
- Thêm nhánh mới (vị trí #2, ngay sau `ApiError`, trước `CastError`): `if (err instanceof multer.MulterError)` → `400`, message từ map trên (fallback `err.message` gốc nếu code lạ), `errorCode: "MULTER_<code>"`.
- Đánh số lại comment các nhánh còn lại (3/4/5) cho khớp thứ tự mới — KHÔNG đổi logic của các nhánh đó.

### 2. `middlewares/upload.middleware.ts` (`uploadExcel`) — dùng `ApiError` thay vì `Error` thô

- `fileFilter`: `cb(new Error("Chỉ cho phép file Excel (.xlsx, .xls)"))` → `cb(ApiError.badRequest(...))` — được nhánh `ApiError` (đã có sẵn, vị trí #1) xử lý đúng 400.

### 3. `services/upload/upload.middleware.ts` (`createUploader`) — tương tự

- `fileFilter`: `cb(new Error("File type not allowed"))` → `cb(ApiError.badRequest("Loại file không được phép"))`.

- Mọi route dùng `uploadExcel` (import Document/Department/Asset) hoặc `createUploader()` (Upload module, Calibration): lỗi sai định dạng/vượt kích thước/vượt số lượng file giờ trả `400` với message rõ ràng (tiếng Việt, mô tả đúng nguyên nhân) thay vì `500` với message thư viện (tiếng Anh, đôi khi khó hiểu với người dùng cuối). Đây là thay đổi CÓ CHỦ ĐÍCH, đúng hướng (400 semantically đúng hơn cho lỗi input người dùng).
