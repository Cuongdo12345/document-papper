# DEV-026 — Backend RBAC Micro-Fix (`GET /users/me` effective permissions)

> Ngày: 2026-09-05. Status: **DONE**. Nguồn gốc: blocker phát hiện trong FE-00 verification (`docs/frontend/tasks/FE-00.md` Mục 10.1).

## Objective

`GET /users/me` trước đây KHÔNG expose đủ thông tin authorization cho Frontend: chỉ populate `role.name` (thiếu `role.isSystemRole`) và không có field permission đã tính sẵn (`extraPermissions`/`denyPermissions` chỉ là ObjectId thô). Micro-fix ADDITIVE, KHÔNG redesign RBAC — chỉ "expose existing RBAC result to FE".

## Root Cause

`getMeService()` (`backend/src/services/users/users.service.ts:490-501`, trước fix) chỉ:
```ts
const user = await User.findById(userId).select("-__v").populate("role", "name").populate("department", "code name");
return user;
```
Trong khi logic tính effective permission (`role.permissions ∪ extraPermissions − denyPermissions`) **đã tồn tại sẵn** và đang chạy đúng ở `authorizePermission.middleware.ts` (qua `getCachedPermissions()` → `getUserEffectivePermissions()`, `permission.service.ts`/`permission.cache.ts`) — chỉ chưa từng được expose ra endpoint này cho FE dùng.

## Changes

### `getMeService()` — thêm `role.isSystemRole` + `permissions: string[]`

`backend/src/services/users/users.service.ts`:
```ts
const user = await User.findById(userId)
  .select("-__v").populate("role", "name isSystemRole")
  .populate("department", "code name");

if (!user || !user.isActive) {
  throw ApiError.badRequest("Không tìm thấy hoặc không hoạt động");
}

const permissions = await getCachedPermissions(userId.toString());

return { ...user.toObject(), permissions };
```

- **`role.isSystemRole`**: field CÓ SẴN trên `Role` model (`role.model.ts`, default `false`) — chỉ thêm vào chuỗi select của populate, không tạo field mới.
- **`permissions: string[]`**: REUSE 100% `getCachedPermissions()` (cache in-memory TTL 5 phút) → `getUserEffectivePermissions()` (đã có sẵn N+1-safe populate + `.filter(Boolean)` chống dangling ref) — **không viết logic tính permission mới, không tạo cache thứ hai**.
- **`extraPermissions`/`denyPermissions`**: GIỮ NGUYÊN dạng ObjectId thô như cũ — additive, không breaking change.
- **ADMIN**: KHÔNG special-case. `permissions[]` trả đúng dữ liệu Role/User thật trong DB — ADMIN bypass permission-check thật vẫn nằm ở `authorizePermission.middleware.ts`, không đổi.

### OpenAPI

`backend/src/docs/openAPI.yaml`:
- `Role` schema — thêm `isSystemRole: {type: boolean, default: false}` (field thật, áp dụng chung mọi chỗ dùng `Role`, không riêng `/me`).
- Schema mới `MeResponseUser` (`allOf: [User, {permissions: string[], role: Role đầy đủ}]`) — CHỈ dùng cho `/api/users/me`, không thêm `permissions` vào schema `User` dùng chung (tránh gây hiểu lầm các endpoint User khác cũng trả field này).
- `GET /api/users/me` — response `data` đổi ref sang `MeResponseUser`, thêm mô tả.

## API Impact

- **Additive, KHÔNG breaking**: mọi field cũ của `GET /users/me` giữ nguyên (`_id`, `username`, `fullName`, `email`, `department`, `extraPermissions`, `denyPermissions`, `isActive`...). Chỉ THÊM `role.isSystemRole` + `permissions[]`.
- Không đổi bất kỳ endpoint nào khác (`POST /auths/login`, `POST /auths/refresh-token`, `GET /users`, `GET /users/:id`... không đụng tới).

## Database Impact

Không có (không đổi schema, không migration — `Role.isSystemRole` đã tồn tại sẵn từ DEV-001A).

## Security Impact

- Auth model: KHÔNG đổi (JWT, refresh token, login/logout flow nguyên vẹn).
- Permission enforcement: KHÔNG đổi (`authorizePermission.middleware.ts` không sửa — vẫn là ranh giới bảo mật thật duy nhất; `/users/me` chỉ EXPOSE thông tin để FE hiển thị UI, không tự enforce authorization nào).
- Permission list không phải secret (đây là authorization context cần thiết cho FE) — không lộ password/token/secret nào thêm.
