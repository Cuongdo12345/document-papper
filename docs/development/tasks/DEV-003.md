# DEV-003 — Bật lại authorization cho `POST /api/documents/proposal`

> Ngày: 2026-09-01. Status: **DONE**. Không mở rộng sang DEV-005/006.

## Objective

Đóng `IMP-003`/`SEC-06`/`RV05-02`/ISS-09: route tạo Document (proposal/report) chỉ yêu cầu `authenticate`, middleware `authorizePermission("DOCUMENT_CREATE")` bị comment — bất kỳ user đã đăng nhập nào cũng tạo được Document bất kể quyền.

## Source Findings

`docs/development/00_DEVELOPMENT_ROADMAP.md` IMP-003; `docs/17_SECURITY_HARDENING_PLAN.md` SEC-06; `docs/module-reviews/05_DOCUMENTS_CODE_REVIEW.md` RV05-02; `docs/12_ISSUES_AND_RISKS.md` ISS-09; `docs/23_CODE_REVIEW_ROADMAP.md` H-02.

## Evidence

`backend/src/routes/documents/document.route.ts:29-35` — route `POST /proposal`: `authenticate` có mặt, dòng `authorizePermission("DOCUMENT_CREATE")` bị comment. Đây là route DUY NHẤT trong file thiếu authorization (đối chiếu toàn bộ route khác trong cùng file — tất cả đều có `authorizePermission(...)` active).

## Dependency đã xử lý trước khi code (theo roadmap Mục 8/Mục 2 IMP-003)

Roadmap yêu cầu: *"cần audit RBAC data trước khi bật"* — xác nhận role dự kiến tạo proposal vẫn giữ `DOCUMENT_CREATE`.

Đã audit **DB dev thật** (script tạm thời, read-only, không ghi dữ liệu, đã xoá sau khi dùng — không commit vào repo):

```
- ADMIN  (isSystemRole=false): DOCUMENT_CREATE=true | total permissions=76
- IT     (isSystemRole=false): DOCUMENT_CREATE=true | total permissions=43
- USER   (isSystemRole=false): DOCUMENT_CREATE=true | total permissions=15
- TRUONG_KHOA      : DOCUMENT_CREATE=false
- DIEU_DUONG_TRUONG: DOCUMENT_CREATE=false
- BAN_GIAM_DOC      : DOCUMENT_CREATE=false
- PHONG_VAT_TU_TTB  : DOCUMENT_CREATE=false
```

Kết quả khớp hoàn toàn với `rolePermission.map.ts` (seed config tĩnh) và đúng thiết kế nghiệp vụ đã ghi chú trong file đó: `USER` là role khởi tạo đề xuất ("user là người khởi tạo đề xuất"), `IT`/`ADMIN` cũng tạo được; 4 role còn lại (`TRUONG_KHOA`, `DIEU_DUONG_TRUONG`, `BAN_GIAM_DOC`, `PHONG_VAT_TU_TTB`) là role DUYỆT (approver), cố tình không có `DOCUMENT_CREATE`. Bật lại guard sẽ **không** chặn nhầm bất kỳ luồng nghiệp vụ hợp lệ nào đang chạy trên DB dev hiện tại.

**Ghi chú ngoài phạm vi (UNKNOWN, không chặn task này)**: dữ liệu RBAC production thật vẫn chưa được xác minh (đã ghi ở Mục 7 roadmap từ trước) — nếu production có role/permission khác dev, cần audit lại riêng ở đó trước khi deploy.

## Implementation

```diff
 router.post(
   "/proposal",
   authenticate,
-  // authorizePermission("DOCUMENT_CREATE"),
+  authorizePermission("DOCUMENT_CREATE"),
   validateBody(CreateDocumentDTO),
   createDocuments,
 );
```

**API Impact**: `POST /api/documents/proposal` — thêm khả năng trả `403 Forbidden` cho user không có `DOCUMENT_CREATE` (trước đây mọi user đăng nhập đều qua được). Request/response shape không đổi cho case hợp lệ.

**Database Impact**: Không.

**RBAC Impact**: Không đổi permission nào — chỉ kích hoạt lại 1 check đã tồn tại sẵn trong middleware, đúng permission đã được gán ở seed data (`ADMIN`/`IT`/`USER`).
