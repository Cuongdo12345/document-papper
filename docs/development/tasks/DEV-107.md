# DEV-107 — BR-21: System Design cache kết quả quét file task 60 giây

**Ngày:** 2026-09-30
**Trạng thái:** DONE
**Loại:** PERFORMANCE

**Nguồn:** `docs/31_BACKEND_CODE_REVIEW.md` BR-21 (LOW).

## 1. Hiện trạng trước khi sửa

`GET /api/system-design` (chỉ người có `SYSTEM_DESIGN_VIEW`) gọi `buildRelatedDocsMap` (`services/systemDesign/relatedDocs.ts`) ở **mỗi request**: đọc **đồng bộ** toàn bộ `docs/development/tasks/*.md` + `docs/frontend/tasks/*.md`, rồi dò chuỗi `models/<module>/` và `features/<module>/` trong từng file cho 12 module.

Đo trên repo lúc sửa: **150 file, 1,27MB, ~40ms mỗi request, trong thời gian đó toàn bộ server bị chặn** (đọc đồng bộ). Số file tăng theo từng task mới. DEV-074 cố ý không cache ("không cần cache phức tạp ở bản đầu").

## 2. Quyết định của user (AskUserQuestion)

- **Cache 60 giây**, giữ nguyên giao diện hàm (vẫn đồng bộ). Không chọn "đọc bất đồng bộ" hay "cả hai".
- Đánh đổi đã nêu và được chấp nhận: thêm/sửa file task xong, trang System Design có thể chậm tối đa 60 giây mới thấy (khởi động lại server là thấy ngay).

## 3. Thay đổi

- `shared/cache/memoryCache.ts`: thêm `getOrSetCacheSync(key, ttlMs, compute)`, bản đồng bộ của `getOrSetCache`. Dùng chung Map, TTL và trần 500 mục của BR-05; `compute` ném lỗi thì không cache gì. `memoryCache` chỉ có bản async nên không dùng trực tiếp được cho hàm đồng bộ này.
- `services/systemDesign/relatedDocs.ts`:
  - hằng số `RELATED_DOCS_CACHE_TTL_MS = 60_000`;
  - `buildRelatedDocsMap` cache **kết quả cuối** (map module → tài liệu liên quan) với khoá gồm repo root và danh sách module (sắp xếp, nên thứ tự không làm hụt cache). Phần đọc file + dò chuỗi tách thành `scanRelatedDocs`, chỉ chạy khi cache hết hạn.
  - Trả về `new Map(...)` mỗi lần, nên nơi gọi sửa Map không làm hỏng cache. Mảng bên trong dùng chung, không được sửa (đã ghi chú trong code).
- Không đổi response, route, permission, frontend hay OpenAPI. `getSystemDesignService` vẫn đồng bộ.

### Bài học trong lúc làm (ghi lại vì ảnh hưởng thiết kế)

Bản đầu chỉ cache **nội dung file** (`readAllTaskFiles`). Đo lại thấy các lần sau vẫn tốn 16–20ms (từ ~40ms), vì phần **dò chuỗi** (12 module × 2 mẫu × 150 file ≈ 30MB văn bản) cũng tốn ~17ms CPU và vẫn chặn server mỗi request. Chuyển sang cache kết quả cuối mới hiệu quả.

## 4. Số đo (cùng máy dev, script đo tạm đã xoá)

| | Trước | Sau |
|---|---|---|
| `buildRelatedDocsMap`, mỗi request | ~40 ms | ~0,2 ms (cache còn hạn) |
| `buildRelatedDocsMap`, lần đầu mỗi 60 giây | ~40 ms | ~75 ms (lần chạy nguội) |
| `getSystemDesignService` cả hàm | ~27–40 ms | ~2 ms (cache còn hạn) |

Đây là số đo trên 1 máy, không phải benchmark chuẩn. Phần còn lại của `getSystemDesignService` (~2ms) là đọc metadata Mongoose, không thuộc BR-21.

## 6. Ghi chú

- Cache nằm trong RAM của 1 process (giống mọi cache khác của dự án): chạy nhiều instance thì mỗi instance giữ riêng, có thể lệch nhau tối đa 60 giây.
- Cache chỉ giữ danh sách đường dẫn/URL (nhỏ, chưa đo chính xác), **không** giữ nội dung 1,27MB của các file.
