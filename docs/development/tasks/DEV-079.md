# DEV-079 — Ảnh đại diện (avatar) cho tài khoản, module User

**Ngày:** 2026-09-24
**Trạng thái:** DONE — user yêu cầu trực tiếp ("Tôi muốn bạn làm thêm tính năng upload, thêm, cập nhật,
xóa ảnh avatar cho tài khoản trong module USER").

## 1. Bối cảnh

Module User trước đây hoàn toàn KHÔNG có field/khái niệm avatar — mọi nơi hiển thị "avatar" (Header) thực
chất chỉ là initials (2 chữ cái đầu tên) dựng từ `fullName`, không có ảnh thật.

## 2. Quyết định nghiệp vụ — đã xác nhận qua AskUserQuestion trước khi code

1. **Phạm vi quyền**: CẢ 2 — self-service (mỗi user tự đổi avatar của mình qua `/app/profile`, không cần
   permission, mirror `PATCH /users/me`) VÀ ADMIN đặt/xoá avatar hộ user khác qua trang Quản lý Users
   (dùng LẠI permission `USER_UPDATE`, không tạo permission riêng).
2. **Lưu & hiển thị ảnh**: lưu THẲNG base64 (data URI đầy đủ) trong document `User` — KHÔNG qua
   file/multer/`Upload` collection riêng. Lý do: dự án hiện KHÔNG có route serving file public/static (mọi
   file khác — vd chứng chỉ kiểm định — đều qua endpoint `/download` xác thực), nên ảnh nhỏ encode base64
   trả thẳng trong response đã xác thực sẵn (`GET /users/me`, `GET /users/:id`) là cách đơn giản nhất để
   `<img src>` dùng được ngay, không cần thêm route/network request nào, không phá vỡ nguyên tắc bảo mật
   "không static/public file serving" đã có chủ đích trong dự án.

## 3. Backend

- **Interface/Model** (`user.interface.ts`/`user.model.ts`): field `avatar?: string` MỚI, `select: false`
  ở schema (CÙNG vai trò với `password`) — loại khỏi MỌI query mặc định (kể cả `GET /users` list), chỉ trả
  về khi tường minh `.select("+avatar")` (đúng 2 nơi: `getMeService`, `getById`) — tránh phồng payload
  danh sách user.
- **DTO** (`users.dto.ts::UpdateAvatarDTO`): validate data URI đúng định dạng `data:image/<jpeg|png|webp>;base64,<...>`
  qua regex, VÀ kích thước GỐC (đã giải mã base64, không tính overhead ~33%) ≤ 300KB. KHÔNG resize
  server-side (dự án chưa có thư viện xử lý ảnh nào — không thêm dependency mới chỉ cho tính năng này).
- **Service** (`users.service.ts`): 2 hàm DÙNG CHUNG `setAvatarService`/`removeAvatarService(userId,
  avatar?, performedBy?)` — `performedBy` optional: self-service (`/me/avatar`) KHÔNG truyền → KHÔNG ghi
  audit (mirror `updateMeService`); ADMIN (`/:id/avatar`) LUÔN truyền → GHI audit `UPDATE` (mirror
  `update()`).
- **Route mới**: `PATCH`/`DELETE /users/me/avatar` (self, chỉ `authenticate`, PHẢI đăng ký TRƯỚC `PUT
  /:id`/`PATCH /:id/avatar` — tránh Express khớp nhầm "me" vào `:id`), `PATCH`/`DELETE /users/:id/avatar`
  (ADMIN, permission `USER_UPDATE`).
- **OpenAPI**: 2 path mới + field `avatar` trên schema `User` (ghi rõ KHÔNG có ở response list) + schema
  `UpdateAvatarRequest` mới. Validate YAML OK.

## 4. Frontend

- **Type/API**: `CurrentUser.avatar`/`UserListItem.avatar` mới, `UpdateAvatarRequest`
  (`auth.types.ts`). 4 hàm API mới: `updateMyAvatar`/`deleteMyAvatar` (`auth.api.ts`, cùng chỗ với
  `getMe`/`updateMe`), `updateUserAvatar`/`deleteUserAvatar` (`users.api.ts`).
- **Utility mới**: `fileToDataUrl.ts` (đọc `File` → data URI qua `FileReader`).
- **Component dùng chung MỚI** `components/shared/Avatar.tsx` — thay initials-only cũ ở `Header.tsx`
  (chuyển `getInitials()` ra `utils/getInitials.ts` riêng để giữ `Avatar.tsx` chỉ export component, tránh
  tăng baseline oxlint warning `only-export-components`). Ưu tiên hiển thị ảnh thật nếu có, fallback
  initials nếu không.
- **Self-service**: `AvatarModal.tsx` (MỚI, `features/profile/`) — tái sử dụng `FileUpload` (component
  dùng chung sẵn có, validate size/type) thay vì viết input file thủ công. Mở từ nút "Đổi ảnh đại diện"
  mới trên `ProfilePage.tsx`.
- **Admin**: `UserAvatarModal.tsx` (MỚI, `features/users/`) — tự fetch chi tiết user qua hook MỚI
  `useUserDetail` (lần đầu tiên `GET /users/:id` có consumer ở FE) để có avatar hiện tại (list không trả
  field này). Mở từ nút hàng mới "Ảnh đại diện" trên `UsersListPage.tsx` (gate `USER_UPDATE`, cùng permission
  nút "Sửa").

## 6. Giới hạn đã biết / ngoài phạm vi (ghi nhận, không tự ý làm thêm)

- KHÔNG resize/nén ảnh server-side — giới hạn cứng 300KB ảnh gốc là cơ chế kiểm soát kích thước duy nhất.
  Nếu sau này cần chấp nhận ảnh lớn hơn/chất lượng cao hơn, cần thêm thư viện xử lý ảnh (vd `sharp`) —
  ngoài phạm vi task này (dự án hiện chưa có dependency loại này).
- `UsersListPage` bảng danh sách KHÔNG có cột avatar (chỉ xem qua modal riêng) — đúng chủ đích tránh phồng
  payload/N+1 request cho mỗi dòng, không phải thiếu sót.
- Route admin `/:id/avatar` dùng lại `USER_UPDATE` — nếu sau này cần tách quyền riêng cho việc quản lý
  avatar (vd cho phép 1 role chỉ sửa avatar mà không sửa được field khác của user), cần permission mới.
