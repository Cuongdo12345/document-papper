# DEV-006 — Hard-delete Document theo tháng → chuyển soft-delete hàng loạt

> Ngày: 2026-09-01. Status: **DONE**. Không thực hiện DEV-005 hoặc task khác.

## Objective

Đóng `IMP-006`/`H-06`(=`ISS-02`=`RV05-05`): `deleteDocumentsByMonthService()` trước đây hard-delete (`Document.deleteMany`) không kiểm tra tham chiếu — để lại dangling reference vĩnh viễn ở 3 model khác (`WorkflowInstance.documentId`, `Document.referenceTo`, `Notification.resourceId`).

**Quyết định nghiệp vụ (user, phiên trước)**: chuyển sang **SOFT-DELETE HÀNG LOẠT**, đồng bộ hoàn toàn với `deleteDocumentService()` (xoá đơn lẻ) — không hard-delete Document.

## Evidence (đã xác minh trước khi code)

- `backend/src/services/documents/document.service.ts:deleteDocumentsByMonthService()` (trước fix) — gọi `deleteDocumentsByFilter()` (`documents.query.ts:73`, `Document.deleteMany(query)`), không transaction, không check reference.
- Đối chiếu `deleteDocumentService()` (cùng file, xoá đơn lẻ) — đã là soft-delete (`isActive=false`, `deletedAt`, `deletedBy`, restorable qua `restoreDocumentService`), ADMIN-only, và có sẵn guard "Missing Validation #5": chặn xoá 1 PROPOSAL nếu còn REPORT active tham chiếu (`countReportsByProposal`).
- Model tham chiếu Document đã xác minh:
  - `backend/src/models/documents/workflowInstance.model.ts:5` — `documentId: ObjectId ref "Document"`.
  - `backend/src/models/documents/document.model.ts:106-113` — `referenceTo: [ObjectId ref "Document"]` (REPORT → PROPOSAL, quan hệ 1-1 theo business rule đã chốt).
  - `backend/src/models/notifications/notification.model.ts:53-59` — `resourceId` (dynamic ref, không `ref` tĩnh) có thể trỏ Document.
- Các query "active flow" đã xác minh đều lọc `isActive: true` sẵn (`documents.query.ts`): `findActiveDocument`, `getActiveDocumentOrFail`, `findProposalById`, `findReportsByProposal`, `countReportsByProposal`, `findPendingRepairProposalForAsset`; `getAllDocumentsService` cũng mặc định `isActive: true` khi client không truyền field này (`document.service.ts:232`). → Soft-delete tự động ẩn document khỏi mọi luồng active hiện có mà KHÔNG cần sửa các hàm này.

## Implementation

```ts
// documents.query.ts
export const softDeleteDocumentsByFilter = (query: any, deletedBy: any) => {
  return Document.updateMany(query, {
    $set: { isActive: false, deletedAt: new Date(), deletedBy },
  });
};

export const findDocumentIdsByFilter = (query: any) => {
  return Document.distinct("_id", query);
};
```

```ts
// document.service.ts — deleteDocumentsByMonthService()
const query = { createdAt: { $gte: start, $lte: end }, ...buildDocumentFilter(filters) };

// Loại PROPOSAL còn REPORT active tham chiếu khỏi batch (đồng bộ guard
// deleteDocumentService — Missing Validation #5).
const proposalIdsInScope = await findDocumentIdsByFilter({ ...query, category: "PROPOSAL" });
const referencedProposalIds = [];
for (const proposalId of proposalIdsInScope) {
  if ((await countReportsByProposal(proposalId)) > 0) referencedProposalIds.push(proposalId);
}
const finalQuery = referencedProposalIds.length
  ? { ...query, _id: { $nin: referencedProposalIds } }
  : query;

const result = await softDeleteDocumentsByFilter(finalQuery, userId);
return { deletedCount: result.modifiedCount, skippedCount: referencedProposalIds.length };
```

**API Impact**: `DELETE /api/documents/delete-by-month` — hành vi đổi từ hard-delete sang soft-delete (dữ liệu KHÔNG còn bị xoá vật lý). Response `data` thêm field mới `skippedCount` (additive, không đổi/xoá `deletedCount` sẵn có, không breaking cho consumer chỉ đọc `deletedCount`). Request body giữ nguyên (`DeleteByMonthRequest` không đổi).

**Database Impact**: Không đổi schema. Chuyển từ 1 lệnh `deleteMany` sang 1 lệnh `updateMany` (cùng 1 collection, cùng lý do KHÔNG cần transaction như comment gốc đã ghi).

**RBAC Impact**: Không đổi — vẫn `authorizePermission("DOCUMENT_DELETE")` ở route, không thêm/bớt permission. (Ghi chú ngoài scope: bulk-delete KHÔNG có guard ADMIN-only như `deleteDocumentService()` — xem "Remaining Issues".)

## Remaining Issues (ghi nhận, KHÔNG tự sửa — ngoài scope quyết định "soft-delete" đã chốt)

- **Authorization gap tồn tại từ trước, KHÔNG phải do DEV-006 tạo ra**: `deleteDocumentsByMonth` chỉ yêu cầu permission `DOCUMENT_DELETE` (route-level), KHÔNG có guard ADMIN-only bổ sung như `deleteDocumentService()` (`isSystemRole===true || role==="ADMIN"`). Dữ liệu seed cho thấy role `USER` cũng có `DOCUMENT_DELETE` (`rolePermission.map.ts`) — nghĩa là 1 user thường có thể soft-delete hàng loạt document của MỌI phòng ban qua endpoint này. Đây là finding SECURITY riêng, không nằm trong yêu cầu DEV-006 ("soft-delete hàng loạt"), không tự sửa theo CLAUDE.md §26 (No Blind Refactoring) — cần task riêng nếu muốn xử lý.
- **`workflowStatus` đang "pending" không được kiểm tra**: nếu 1 PROPOSAL đang chờ duyệt (`workflowStatus: "pending"`) bị soft-delete qua batch tháng, KHÔNG có guard chặn — giống hệt hành vi hiện có của `deleteDocumentService()` (xoá đơn lẻ cũng không check `workflowStatus`), nên đây là gap CÓ SẴN trong codebase, không phải regression do DEV-006, không mở rộng sửa.
- Chưa có automated test cho `deleteDocumentsByMonthService`/route `delete-by-month` (không có suite nào cho `document.service.ts` từ trước).
