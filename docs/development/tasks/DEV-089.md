# DEV-089 — Đồng bộ khoa/phòng từ Excel: kiểm tra định dạng + xem trước + chọn khoa cần tạo

**Ngày:** 2026-09-28
**Trạng thái:** DONE

**Nguồn:** User yêu cầu sau phát hiện ở FE-38 Mục 4 (11 "khoa" mang tên thiết bị trên DB dev): "xem trước danh sách khoa đã tạo, kiểm tra có đúng định dạng file trước khi đồng bộ".

## 1. Khảo sát: 4 lỗi của `syncDepartmentFromExcel` bản cũ

1. Đọc **cột 3 của file bất kỳ**, không kiểm tra tiêu đề cột. Import tài liệu và tài sản đã có `validateImportHeaderRow`, riêng chức năng này bị sót.
   File mẫu import **tài sản** có cột 3 là "Tên tài sản" (cột "Khoa/phòng" ở cột 4). Tải file tài sản/thiết bị vào đây là tên thiết bị thành khoa, khớp đúng 11 khoa lạ.
2. Không có bước xem trước: chọn file là tạo ngay.
3. Mã tự sinh chỉ lấy 10 ký tự đầu (`generateDepartmentCode`). Hai tên dài giống nhau (vd "Thiết bị quang châm 2/4 kênh") ra cùng mã. `insertMany` lỗi ngầm, response chỉ trả con số.
4. Khoa trùng tên khoa **đã xoá mềm** (DEV-086) bị đếm là "đã tồn tại", user không biết khoa đó đang ẩn.

## 2. Quyết định của user (AskUserQuestion)

- Định dạng hợp lệ: **dòng 1 có cột tiêu đề "Khoa" hoặc "Khoa/Phòng", ở vị trí bất kỳ**. Không bắt đủ 10 cột như file mẫu tài liệu, không tạo file mẫu riêng.
- Xem trước: **tick chọn từng khoa** trước khi tạo, mặc định chọn hết.

## 3. Backend

**`excel.service.ts::syncDepartmentFromExcel(buffer, { dryRun, names })`** (viết lại):
- Tìm cột theo `DEPARTMENT_SYNC_HEADERS` (`excel.constants.ts`). So khớp sau chuẩn hoá: chữ thường, gộp khoảng trắng, bỏ khoảng trắng quanh "/".
- Không tìm thấy cột → 400, kèm `details.foundHeaders`.
- Gộp tên trùng không phân biệt hoa/thường, rồi phân loại:
  - `toCreate`: sẽ tạo mới, kèm mã tự sinh.
  - `existed`: đã có.
  - `inactive`: trùng tên khoa đang ẩn. **Không** tự khôi phục.
  - `invalid`: không sinh được mã, hoặc mã trùng khoa có sẵn / trùng tên khác trong file, kèm lý do.
- `dryRun` → trả bản xem trước, **không ghi DB**.
- Tạo thật → luôn **tự phân loại lại từ file**. `names` chỉ là bộ lọc; tên không thuộc `toCreate` bị bỏ qua.
- Trả `created` + `failed` từng dòng (trước đây chỉ `console.error`).

**Controller và hợp đồng API:**
- `excel.controller.ts`: đọc `?dryRun=true` (cùng quy ước import tài liệu).
- Trường multipart `names` là chuỗi JSON mảng. Parse bằng zod (≤ 5000 tên, mỗi tên ≤ 200 ký tự); sai định dạng → 400.
- Route và permission **không đổi**: `POST /export/departments/sync-from-excel`, `EXCEL_DEPARTMENT_SYNC`.
- Response đổi shape, thay `{totalInFile, created: number, existed: number}` cũ. Consumer duy nhất là `DepartmentSyncModal`, đã cập nhật cùng lúc.
- OpenAPI: thêm param `dryRun`, field `names`, schema response chi tiết, `DepartmentSyncItem`/`DepartmentSyncIssue`, và 403.

## 4. Frontend

- **`DepartmentSyncModal.tsx`** viết lại thành 3 bước: chọn file → **xem trước** → kết quả.
  - Bước xem trước: cho biết cột đã đọc, danh sách "Sẽ tạo mới" có checkbox (chọn tất cả / từng dòng, kèm mã tự sinh), cùng các nhóm "Không tạo được", "Đang ẩn" (hướng dẫn khôi phục ở trang Khoa/Phòng) và "Đã tồn tại — bỏ qua".
  - Nút "Tạo N khoa/phòng" khớp với màn kết quả "Đã tạo N khoa/phòng".
  - Khi file sai định dạng: hiện lỗi kèm "Các cột tìm thấy ở dòng 1: …".
- `useSyncDepartmentsExcel.ts`: thêm `usePreviewDepartmentSync` (dryRun, không invalidate). `useSyncDepartmentsExcel` nhận `{ file, names }`.
- `documentExcel.api.ts`, `department.types.ts` (`DepartmentSyncResult`/`Item`/`Issue`).
