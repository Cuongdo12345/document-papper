# DEV-101 — BR-12: escape regex ở tìm kiếm user và tìm phiên đăng nhập

**Ngày:** 2026-09-30
**Trạng thái:** DONE
**Loại:** SECURITY, BUG FIX

**Nguồn:** `docs/31_BACKEND_CODE_REVIEW.md` BR-12 (LOW).

## 1. Hiện trạng trước khi sửa

`services/users/users.service.ts` đưa thẳng input của client vào `$regex` ở 3 chỗ, là 3 chỗ duy nhất còn sót. Rà toàn bộ `src/`: mọi `$regex` khác đều đã dùng `escapeRegex` từ DEV-010/IMP-015.

- `getList` (`GET /api/users?keyword=`): `filter.username = { $regex: keyword }`.
- `listAllSessions` (`GET /api/users/sessions?search=`): `username` và `fullName` với `$regex: search`.

Hậu quả:
- Ký tự như `(` hoặc `[` làm MongoDB báo lỗi regex, và API trả **500**.
- Ký tự như `.` được hiểu là "bất kỳ ký tự nào", nên kết quả tìm kiếm sai.
- Mở cửa cho regex injection / ReDoS. DTO giới hạn độ dài 100 ký tự, nên đã được giảm thiểu một phần.

## 2. Thay đổi

- `users.service.ts`: import `escapeRegex` từ `shared/utils/regex.util.ts` (tái dùng, không viết mới). Escape `keyword` trong `getList` và `search` trong `listAllSessions`.
- Hành vi thay đổi: ô tìm kiếm khớp **đúng ký tự** người dùng gõ. Không đổi API contract, không đổi frontend, không đổi OpenAPI.

## 3. Test

- E2E mới `__tests__/e2e/user-search-regex.e2e-test.ts` (5 test, HTTP thật):
  - `keyword=(` → 200 rỗng;
  - `keyword=br12.axb` → không khớp `br12_axb`;
  - `keyword=br12_` → vẫn tìm đúng 3 user (đối chứng);
  - `sessions?search=(có ngoặc)` → khớp đúng phiên của user có ngoặc trong họ tên;
  - `sessions?search=[` → 200 rỗng.
- **Đã kiểm chứng test bắt được lỗi:** tạm gỡ `escapeRegex` thì 3/5 test fail (đúng 3 case lỗi); khôi phục thì 5/5 pass.
