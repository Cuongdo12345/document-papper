# DEV-015 — Injection/Output Hardening (CSV formula, path traversal, HTML email)

> Ngày: 2026-09-01. Status: **DONE**. IMP-021 = MEDIUM-07 + MEDIUM-08 + MEDIUM-10.

## Objective

3 vấn đề "output không neutralize input người dùng" — khác các finding injection trước đó (NoSQL — đã xử lý DEV-008; regex ReDoS — đã xử lý DEV-010), đây là injection ở tầng OUTPUT (file người dùng nhận, HTML email), gộp 1 task theo đúng nhóm roadmap.

## Root Cause / Evidence (đã verify lại trên source hiện tại)

- `backend/src/services/users/userAudits.service.ts:escapeCsvField` — chỉ escape theo RFC 4180 (`"`, `,`, `\n`, `\r`), KHÔNG neutralize ký tự kích hoạt công thức Excel (`=`, `+`, `-`, `@`). Cột `note` (free-text) trong `AUDIT_EXPORT_COLUMNS` có khả năng chứa input gián tiếp.
- `backend/src/services/upload/upload.middleware.ts:storage.filename` — `${Date.now()}-${file.originalname}`, không qua `path.basename()` — `file.originalname` do client gửi (multipart header), có thể chứa `../`. Xác nhận: `certificateUploader` (`medicalDevice.routes.ts:40`) dùng CHUNG `createUploader()` → chung `storage` này, nên 1 fix đóng cả 2 endpoint (`POST /api/upload` và certificate upload).
- `backend/src/services/notifications/notification.service.ts:sendEmailForNotification` — `html: \`<p>${message}</p>\`` nội suy trực tiếp, không escape. `message` có thể chứa `Document.title` (free-text).
- `backend/src/shared/helpers/passwordReset.template.ts:buildPasswordResetEmail` — `greeting = fullName ? \`Xin chào ${fullName},\` : ...` nội suy trực tiếp vào `html`, không escape. `fullName` là free-text user tự đặt.
- Không có utility escape HTML nào có sẵn trong codebase (đã grep `escapeHtml`/`sanitizeHtml`/dependency `dompurify`/`sanitize-html` trong `package.json` — không có).

## Changes

### 1. MEDIUM-07 — CSV Formula Injection

- `userAudits.service.ts:escapeCsvField` — thêm bước prefix `'` cho field bắt đầu bằng `=`/`+`/`-`/`@`/tab, TRƯỚC khi áp quy tắc quoting RFC 4180 hiện có (không đổi logic quoting cũ).

### 2. MEDIUM-08 — Path Traversal qua `originalname`

- `upload.middleware.ts:storage.filename` — `file.originalname` → `path.basename(file.originalname)` trước khi ghép với `Date.now()`. `path` đã import sẵn trong file, không cần thêm.

### 3. MEDIUM-10 — HTML/Email Injection

- **File mới**: `backend/src/shared/utils/html.util.ts` — `escapeHtml()`, escape 5 ký tự HTML cơ bản (`&<>"'`). Không thêm dependency ngoài (`dompurify`/`sanitize-html`) — chỉ cần escape text node đơn giản, không có nhu cầu render rich HTML từ input người dùng (đúng CLAUDE.md §25 — ưu tiên simple solution hơn new dependency).
- `notification.service.ts:sendEmailForNotification` — `html: \`<p>${escapeHtml(message)}</p>\``.
- `passwordReset.template.ts:buildPasswordResetEmail` — `greeting` (dùng cho `html`) escape `fullName`; thêm biến `greetingText` riêng (KHÔNG escape) dùng cho bản `text` thuần — tránh hiển thị `&amp;`/`&#39;`... literal trong email client không hỗ trợ HTML.

## API Impact

- `GET /audit/export?format=csv`: field `note` (và mọi field khác) bắt đầu bằng `=`/`+`/`-`/`@`/tab giờ có thêm prefix `'` khi mở bằng Excel — thay đổi hiển thị NHỎ (chỉ áp dụng cho giá trị vốn đã bắt đầu bằng các ký tự hiếm gặp trong dữ liệu audit log thật), không đổi response shape (vẫn là file CSV).
- `POST /api/upload`, certificate upload (Calibration): tên file lưu trên đĩa (KHÔNG PHẢI tên hiển thị `fileName` lưu trong DB — vẫn giữ `file.originalname` gốc, xem `upload.service.ts`/`calibrationRecord.service.ts`) nay bỏ mọi phần thư mục nếu `originalname` chứa `../` — chỉ ảnh hưởng trường hợp client cố tình gửi filename có path traversal, không ảnh hưởng file bình thường.
- Email (notification, reset password): nội dung hiển thị escape HTML entity nếu `message`/`fullName` chứa ký tự `&<>"'` — thay đổi hiển thị nhỏ trong trường hợp hiếm (tên/tiêu đề chứa ký tự này), không đổi luồng gửi mail.
