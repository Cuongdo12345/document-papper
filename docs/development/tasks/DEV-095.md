# DEV-095 — BR-07: thêm index `documentId` cho `WorkflowInstance`

**Ngày:** 2026-09-29
**Trạng thái:** DONE
**Loại:** PERFORMANCE, DATABASE (chỉ thêm index)

**Nguồn:** `docs/31_BACKEND_CODE_REVIEW.md` BR-07 (MEDIUM). Không có quyết định nghiệp vụ nào cần hỏi.

## 1. Hiện trạng trước khi sửa

`models/documents/workflowInstance.model.ts` chỉ có 2 index `{status:1, createdAt:1}` và `{"steps.role":1, createdAt:-1}`. Mọi truy vấn theo `documentId` đều quét toàn collection.

| Nơi gọi | Truy vấn | Tần suất |
|---|---|---|
| `loadDocument.middleware.ts:67` | `{documentId, status:"pending"}` sort `createdAt:-1` | mỗi lần mở chi tiết tài liệu, lịch sử phiên bản, xuất PDF |
| `loadDocument.middleware.ts:91` | `{documentId}`, lấy `steps.role` | như trên |
| `workflow.service.ts::submitWorkflow` (BR-02, trong transaction) | `{documentId}` sort `createdAt:-1` | mỗi lần gửi duyệt |
| `workflow.service.ts::getWorkflowByDocument` | `{documentId}` sort `createdAt:-1` | mỗi lần xem workflow của tài liệu |
| `document.service.ts::getReportsByProposalService` | `exists({documentId, "steps.role"})` | xem biên bản của đề xuất khác khoa |

## 2. Thay đổi

`workflowInstance.model.ts`: thêm `workflowInstanceSchema.index({ documentId: 1, createdAt: -1 })`, **không unique**, vì một tài liệu có nhiều workflow khi gửi duyệt lại.
- Tiền tố `documentId` (so khớp bằng) cộng `createdAt:-1` trùng đúng thứ tự sort. Nhờ vậy `findOne(...).sort({createdAt:-1})` đọc thẳng bản mới nhất, không cần bước SORT.
- Không đổi field, logic hay API nào.

## 3. Áp dụng trên DB

- `config/database/database.ts` bật `autoIndex: true`, nên Mongoose tự tạo index khi server khởi động.
- Trên DB dev, index `documentId_1_createdAt_-1` **đã có ngay sau khi sửa model**: server dev (ts-node-dev `--respawn`) đã tự khởi động lại. Script kiểm tra tạm gọi thêm `createIndexes()`, chỉ tạo index còn thiếu, không xoá gì; danh sách index trước và sau giống nhau.
- **Production**: nếu sau này tắt `autoIndex` (comment trong `database.ts` có gợi ý), cần tạo index này thủ công bằng `WorkflowInstance.createIndexes()` hoặc `db.workflowinstances.createIndex({documentId:1, createdAt:-1})`. Bảng hiện rất nhỏ (9 bản ghi), nên tạo index gần như tức thì.

## 4. Kiểm tra bằng `explain("executionStats")` trên DB dev

| Truy vấn | Kế hoạch thắng | docsExamined / nReturned |
|---|---|---|
| loadDocument: tất cả workflow của tài liệu | `IXSCAN(documentId_1_createdAt_-1)` | 2 / 2 |
| submit / getByDocument: bản mới nhất | `IXSCAN(documentId_1_createdAt_-1)` + LIMIT | 1 / 1 |
| reports: `exists` theo `steps.role` | `IXSCAN(documentId_1_createdAt_-1)` + LIMIT | 1 / 1 |
| loadDocument: bản `pending` mới nhất | `IXSCAN(status_1_createdAt_1)` | 0 / 0 |

Truy vấn cuối chọn index `status` vì DB dev đang có **0** workflow `pending`, nên đó là kế hoạch đọc 0 bản ghi. Khi có nhiều workflow `pending`, query planner của MongoDB tự so các kế hoạch ứng viên, trong đó có index mới.
