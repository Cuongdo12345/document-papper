# DEV-028 — Bổ sung `GET /workflows/templates` (đọc-only)

> Ngày: 2026-09-05. Status: **DONE**. Nguồn gốc: phát hiện khi code FE-04 (Documents Core UI) — cần dropdown chọn `templateId` cho action "Submit vào workflow" (`POST /workflows/submit`), nhưng không có endpoint nào liệt kê lại `WorkflowTemplate` đã tạo. User xác nhận rõ ràng qua `AskUserQuestion`: chọn phương án bổ sung endpoint (không bỏ qua tính năng Submit).

## Objective

`workflow.routes.ts` trước đây chỉ có `POST /workflows/templates` (tạo mới, permission `WORKFLOW_TEMPLATE_CREATE`) — KHÔNG có route GET nào để liệt kê lại. Không có seed script nào tạo `WorkflowTemplate` mẫu. Kết quả: FE không có cách nào hiển thị danh sách template cho người dùng chọn khi submit 1 document vào workflow, dù dữ liệu template THẬT đã tồn tại trong DB (tạo thủ công qua Postman/API trước đó — xác nhận qua HTTP thật, xem Mục "HTTP Verification").

## Root Cause (gap, không phải bug)

`backend/src/services/documents/workflow.service.ts` chỉ có `createWorkflowTemplate()` — hàm DUY NHẤT thao tác model `WorkflowTemplate`. Route (`workflow.routes.ts`) tương ứng cũng chỉ có `POST /templates`. Không phải lỗi logic — đơn giản là tính năng "xem lại template" chưa từng được implement.

## Changes

### 1. `backend/src/services/documents/workflow.service.ts`
Thêm `getAllWorkflowTemplatesService()` ngay sau `createWorkflowTemplate()` — hàm THUẦN ĐỌC:
```ts
export const getAllWorkflowTemplatesService = async () => {
  return await WorkflowTemplate.find({ isActive: true })
    .select("name steps isActive createdAt")
    .sort({ name: 1 });
};
```
Chỉ trả template `isActive: true` — template đã tắt không nên xuất hiện trong dropdown chọn submit workflow MỚI (không ảnh hưởng gì tới `WorkflowInstance` đã tạo trước đó, vì `submitWorkflow()` copy nguyên `steps[]` vào instance tại thời điểm submit, không giữ tham chiếu sống tới template).

Không sửa bất kỳ hàm nào khác trong file (`submitWorkflow`, `approveStep`, `rejectStep`, `cancelWorkflow`, `completeWorkflow`, `getWorkflowById`, `getWorkflowByDocument`, `getPendingApprovalsForRole` — tất cả giữ nguyên 100%).

### 2. `backend/src/controllers/documents/workflow.controller.ts`
Thêm `getTemplates` — theo đúng pattern `catchAsync` + response `{success:true, message, data}` nhất quán với các handler khác trong file.

### 3. `backend/src/routes/documents/workflow.routes.ts`
Thêm route:
```ts
router.get("/templates", authenticate, authorizePermission("WORKFLOW_VIEW"), getTemplates);
```
Đặt CÙNG NHÓM với `/pending` và `/document/:documentId` — TRƯỚC `router.get("/:id", ...)` (thứ tự route quan trọng với Express, "templates" phải khớp static path trước khi rơi vào `:id` catch-all).

**Permission**: dùng lại `WORKFLOW_VIEW` (đã tồn tại, KHÔNG tạo permission mới) — catalog hiện tại không có permission "xem template" riêng, và ngữ nghĩa "xem template để chọn khi submit workflow" khớp đúng với `WORKFLOW_VIEW` (đã dùng cho `/pending`, `/document/:documentId`).

## API Impact

**Endpoint mới** (không đổi endpoint nào có sẵn):
```
GET /api/workflows/templates
Permission: WORKFLOW_VIEW
Response: {success:true, message, data: WorkflowTemplate[]}
```
Đây là ADDITIVE THUẦN TUÝ — không breaking change cho bất kỳ consumer nào hiện có (chưa có FE nào gọi `POST /workflows/templates` để tạo, và route GET mới hoàn toàn tách biệt).

`docs/00_PROJECT_MEMORY.md`/OpenAPI CHƯA cập nhật endpoint này — ghi nhận ở Remaining Issues.
