# DEV-069 — Roadmap C2: Quản lý phiên đăng nhập (Session Management)

**Ngày:** 2026-09-19. **Status:** DONE. **Nguồn gốc:** user yêu cầu trực tiếp làm mục C2 trong
`docs/development/FEATURE_DEVELOPMENT_ROADMAP.md` (mới chỉ là ý tưởng phác thảo "💡") — đã hỏi lại
scoping trước khi code, theo đúng thông lệ B/C-series.

## 1. Xác nhận scope với user (AskUserQuestion) trước khi code

1. **Thông tin thiết bị**: user chọn **"Thêm User-Agent + IP"** — `RefreshToken` trước đây KHÔNG lưu bất
   kỳ metadata thiết bị nào (chỉ token hash/expiresAt/revoked).
2. **Phạm vi thu hồi**: user chọn **"Cả 2: tự quản lý + ADMIN hỗ trợ"** — mọi user tự xem/thu hồi phiên
   của mình, CỘNG THÊM ADMIN xem/thu hồi được phiên của người khác (permission riêng).
3. **Đối tượng áp dụng**: user chọn **"TẤT CẢ user"** — KHÁC 2FA (C1, chỉ ADMIN + role duyệt cấp cao) vì
   đây là vệ sinh bảo mật cơ bản, hợp lý cho mọi tài khoản.
4. **Thu hồi phiên hiện tại**: user chọn **"Cho phép + tự đăng xuất ngay"** — vẫn cho thu hồi phiên đang
   dùng để xem trang, tự động đăng xuất cục bộ ngay sau khi thành công.

## 2. Rà soát hiện trạng trước khi code (evidence)

- `RefreshToken` model (`refreshToken.model.ts`) — CHỈ có `{user, token(hash), expiresAt, revoked}`,
  KHÔNG có index nào (kể cả `user`) — mỗi lần `refresh()`/revoke đều collection-scan.
- `login()`/`refresh()` (`auths.service.ts`) — `login()` chỉ nhận `(username, password)`, KHÔNG có
  `req`, không capture được User-Agent/IP. `refresh()` KHÔNG rotate refresh token (dùng lại token cũ tới
  khi hết hạn/bị revoke) — xác nhận docstring gốc.
- Mọi pathway `revoked:true` hiện có (`logout`, `resetPassword`, `disable`, `changePassword`,
  `resetPasswordByAdmin`) đều là "revoke theo raw token của chính mình" hoặc "revoke TOÀN BỘ token của 1
  user" — KHÔNG có pathway "revoke 1 token cụ thể theo id do user chọn từ danh sách".
- `USER_RESET_PASSWORD` xác nhận (từ DEV-068) KHÔNG gán role nào trong `rolePermission.map.ts` — mirror
  pattern này cho `SESSION_VIEW_ALL`/`SESSION_REVOKE_ALL`.

## 3. Backend

### Model — `RefreshToken` (`refreshToken.model.ts`)
Thêm `userAgent`/`ip` (String, optional — token cũ trước migration hiển thị "Không xác định", không cần
backfill). Thêm index `{user:1, revoked:1, createdAt:-1}` (trước đây model này KHÔNG có index nào).

### Helper mới — `parseUserAgent()` (`shared/helpers/userAgent.helper.ts`)
Tự viết regex đơn giản (KHÔNG cài `ua-parser-js`, CLAUDE.md Mục 25 — chỉ cần đúng browser+os, không cần
độ chính xác đầy đủ mà thư viện chuyên dụng cung cấp). **Bug thật phát hiện qua unit test**: UA thật của
Safari/iOS luôn chứa chuỗi tương thích ngược "like Mac OS X" — nếu check `Mac OS X` TRƯỚC `iPhone/iPad`,
mọi thiết bị iOS bị nhận nhầm thành macOS. Đã sửa thứ tự check (iOS trước Mac OS X).

### `auths.service.ts` — self-service
- `issueLoginTokens()`/`login()`/`verifyLoginOtp()` — thêm tham số `meta: {userAgent?, ip?}`, đính kèm
  vào `RefreshToken.create()`.
- `listMySessions(userId, meta)` (MỚI) — chỉ trả phiên CÒN hiệu lực (`revoked:false` VÀ chưa hết hạn).
  `isCurrent` xác định bằng HEURISTIC so khớp `userAgent`+`ip` của request hiện tại với từng phiên đã lưu
  — KHÔNG cần client gửi lại refreshToken (tránh truyền token nhạy cảm qua body của API "chỉ xem"). Đánh
  đổi: lý thuyết sai nếu 2 thiết bị THẬT SỰ trùng cả UA lẫn IP (hiếm) — chấp nhận được, không phải cơ chế
  bảo mật, chỉ phục vụ hiển thị.
- `revokeMySession(userId, sessionId)` (MỚI) — chỉ thu hồi phiên CỦA CHÍNH MÌNH, trả 404 (không phải
  403) nếu không tồn tại/thuộc user khác — tránh lộ thông tin phiên đó có tồn tại hay không.

### `users.service.ts` — ADMIN thao tác trên user khác
- `listUserSessions(targetUserId)` (MỚI) — permission `SESSION_VIEW_ALL`. KHÔNG có field `isCurrent`
  (ADMIN xem hộ, không phải phiên của chính họ).
- `revokeUserSession(targetUserId, sessionId, performedBy)` (MỚI) — permission `SESSION_REVOKE_ALL`
  (TÁCH RIÊNG khỏi VIEW — thu hồi rủi ro cao hơn xem), ghi audit `REVOKE_SESSION`.

### Permission mới — `permission.constant.ts`
`SESSION_VIEW_ALL`/`SESSION_REVOKE_ALL` — mirror `USER_RESET_PASSWORD`/`USER_RESET_2FA`: KHÔNG gán role
nào trong `rolePermission.map.ts`, chỉ ADMIN có qua wildcard. Tự xem/thu hồi phiên CHÍNH MÌNH KHÔNG cần
permission riêng (action tự-scope qua `req.user!._id`, giống `changePassword`/2FA-self).

### Route mới
- `GET /auths/sessions`, `DELETE /auths/sessions/:id` (self-service, `authenticate`).
- `GET /users/:id/sessions` (permission `SESSION_VIEW_ALL`), `DELETE /users/:id/sessions/:sessionId`
  (permission `SESSION_REVOKE_ALL`) — route ĐẦU TIÊN trong codebase có 2 ObjectId param lồng nhau
  (`UserSessionParamDTO` mới, `users.dto.ts`).

## 5. Việc CẦN LÀM THÊM (vận hành, không phải code thiếu)

- Vào UI "Phân quyền" gán `SESSION_VIEW_ALL`+`SESSION_REVOKE_ALL` cho role ADMIN (Permission catalog đã
  có sẵn để chọn, xem Mục 3).
- Không có migration DB bắt buộc — `userAgent`/`ip` optional, phiên cũ (trước migration) vẫn hoạt động
  bình thường, chỉ hiển thị "Không xác định" thay vì tên trình duyệt/hệ điều hành thật.
- Nếu deploy sau reverse proxy (Nginx...) mà chưa bật `app.set("trust proxy", ...)`, `ip` ghi lại sẽ là
  IP của proxy, không phải IP thật của client — ngoài phạm vi task này (cấu hình hạ tầng deploy).
