## 4b. Hai lỗi runtime lộ ra khi chạy e2e với driver mongodb 7.6

1. **Lỗi thật, ảnh hưởng cả production:** `deleteDocumentsByMonthService` (code của DEV-098) chạy 2 truy vấn `distinct` **song song (`Promise.all`) trên cùng một session trong transaction**. Driver 7.6 gửi `startTransaction` ở cả hai, nên server trả `"Only servers in a sharded cluster can start a new transaction at the active transaction number"` và API trả 500.
   - MongoDB vốn không hỗ trợ thao tác song song trong một transaction; driver cũ chỉ tình cờ chịu được.
   - Sửa: chạy 2 truy vấn **tuần tự**. Thứ tự gọi giữ nguyên, nên unit test không đổi.
   - Đã rà toàn bộ `src/`: không còn chỗ nào khác dùng `Promise.all` với session. `users.service.ts:659` là biến `sessions` (phiên đăng nhập), không phải DB session.
2. **Chỉ trong môi trường jest:** driver 7.6 nạp `os` bằng `import('os')` động. Sandbox CommonJS của jest không hỗ trợ việc này, lỗi bị nuốt, metadata handshake thành `{}`, và server từ chối với `"Missing required sub-document 'driver' in the client metadata document"`, khiến mọi suite e2e treo hoặc fail.
   - Sửa trong `__tests__/e2e/setup.ts`: `mongoose.connect(uri, { runtimeAdapters: { os } })`. Đây là option chính thức của driver.
   - App chạy bằng node thường không bị: đã thử kết nối bằng script ts-node ngoài jest và thành công. Server Playwright cũng không bị, vì chạy bằng ts-node.
