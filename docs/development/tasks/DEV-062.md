## 1. Rà soát trước khi code — phát hiện quan trọng

Trước khi thêm bulk-restore, đã kiểm tra khả năng khôi phục ĐƠN LẺ đã tồn tại của từng domain (qua agent
điều tra đọc trực tiếp source), phát hiện **2 kiểu khác nhau**:

| Domain | Restore đơn lẻ | Cách khôi phục |
|---|---|---|
| Asset | `restoreAssetService` (dedicated) | `PATCH /assets/:id/restore`, permission `ASSET_UPDATE` |
| AssetCategory | `restoreAssetCategoryService` (dedicated) | `PATCH /assets/asset-categories/:id/restore`, permission `ASSET_CATEGORY_UPDATE` |
| ConsumableCategory | `restoreConsumableCategoryService` (dedicated) | `PATCH /inventory/categories/:id/restore`, permission `CONSUMABLE_CATEGORY_UPDATE` |
| User | `restore` (dedicated, ghi UserAudit) | `PATCH /users/restore/:id`, permission RIÊNG `USER_RESTORE` (khác `USER_DELETE`) |
| ConsumableItem | **KHÔNG có route/service restore đơn lẻ nào** | Frontend tự "giả lập" bằng `updateConsumableItemService(id, {isActive:true})`, permission `CONSUMABLE_UPDATE` |
| Vendor | **KHÔNG có route/service restore đơn lẻ nào** | Frontend tự "giả lập" bằng `updateVendorService(id, {isActive:true})`, permission `VENDOR_UPDATE` |

Quyết định: bulk-restore của ConsumableItem/Vendor tái dùng ĐÚNG cách "giả lập qua update" đó (không tự ý
xây route restore đơn lẻ mới — ngoài scope, sẽ là thay đổi kiến trúc lớn hơn yêu cầu).

## 2. Backend — 6 service function mới, mỗi domain: `runBulkDelete` + route `POST .../bulk-restore`

| Domain | Service mới | Gọi lại (single-item) | Permission | Route |
|---|---|---|---|---|
| Asset | `bulkRestoreAssetService` | `restoreAssetService` | `ASSET_UPDATE` | `POST /assets/bulk-restore` |
| AssetCategory | `bulkRestoreAssetCategoryService` | `restoreAssetCategoryService` | `ASSET_CATEGORY_UPDATE` | `POST /assets/asset-categories/bulk-restore` |
| ConsumableItem | `bulkRestoreConsumableItemService` | `updateConsumableItemService({isActive:true})` | `CONSUMABLE_UPDATE` | `POST /inventory/items/bulk-restore` |
| ConsumableCategory | `bulkRestoreConsumableCategoryService` | `restoreConsumableCategoryService` | `CONSUMABLE_CATEGORY_UPDATE` | `POST /inventory/categories/bulk-restore` |
| Vendor | `bulkRestoreVendorService` | `updateVendorService({isActive:true})` | `VENDOR_UPDATE` | `POST /vendors/bulk-restore` |
| User | `bulkRestore` (users.service.ts) | `restore` | `USER_RESTORE` | `POST /users/bulk-restore` |

### Khác biệt cách wiring theo số lượng permission của từng trang
- **1 permission chung** cho cả xoá/khôi phục hàng loạt (ConsumableItem: `CONSUMABLE_UPDATE`, Vendor:
  `VENDOR_UPDATE`) → giữ nguyên `PermissionGuard` bọc `BatchActionBar` có sẵn, chỉ thêm prop `onRestore`.
- **2 permission khác nhau** (Asset: `ASSET_DELETE` vs `ASSET_UPDATE`; AssetCategory:
  `ASSET_CATEGORY_DELETE` vs `ASSET_CATEGORY_UPDATE`; ConsumableCategory:
  `CONSUMABLE_CATEGORY_DELETE` vs `CONSUMABLE_CATEGORY_UPDATE`; User: `USER_DELETE` vs `USER_RESTORE`) →
  đổi từ `PermissionGuard` bọc ngoài sang tính `canBulkDelete`/`canBulkRestore`/`canBulkAct` qua
  `usePermission().hasPermission()` (cùng pattern đã dùng ở `DocumentsListPage`, DEV-061) — `BatchActionBar`
  chỉ nhận `onDelete`/`onRestore` tương ứng permission nào có, `selection` prop trên `DataTable` chỉ bật khi
  `canBulkAct`.
- `components/shared/BatchActionBar.tsx`: KHÔNG cần sửa thêm — `onDelete`/`onRestore` đã tuỳ chọn từ
  `DEV-061`.
