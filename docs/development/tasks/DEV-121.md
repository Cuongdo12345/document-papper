## 2. Thay đổi

1. **`.github/workflows/ci.yml`** (mới) — 2 job song song trên `ubuntu-latest`, Node 22, cache npm theo từng `package-lock.json`, `permissions: contents: read`, huỷ lần chạy cũ khi có push mới cùng nhánh:
   - **backend**: `npm ci` → `npx tsc --noEmit` → `npm test` (unit, mock DB) → `npm run build`.
   - **frontend**: `npm ci` → `npm run lint` (oxlint) → `npm test` (vitest) → `npm run build` (gồm `tsc -b`).
   - Không cần secret: unit test backend dùng mock, không đọc `.env`; e2e (khi thêm) tự đặt biến môi trường trong `src/__tests__/e2e/setup.ts`.
   - Chưa gồm: e2e backend (xem mục 4), Playwright (ảnh baseline `*-chromium-win32.png` chỉ so được trên Windows; chạy trên Linux sẽ luôn lệch).
2. **Sửa lỗi thật tìm ra khi mô phỏng CI:** `npm run build` gọi `backend/scripts/copy-static-assets.js`, nhưng cả `scripts/` bị `.gitignore` (ở gốc repo VÀ ở `backend/`) → **mọi bản clone repo (CI, máy chủ production) đều không build được backend** (`MODULE_NOT_FOUND`). Sửa:
   - `.gitignore` gốc: `scripts` → `**/scripts/*` (chỉ bỏ qua nội dung, để thư mục con có thể giữ lại file).
   - `backend/.gitignore`: `scripts` → `scripts/*` + `!scripts/copy-static-assets.js`.
   - Kết quả: CHỈ `copy-static-assets.js` được theo dõi; các script vận hành khác (seed/migrate, `remove-legacy-asset-permissions.ts`...) VẪN bị bỏ qua như trước (kiểm bằng `git check-ignore`). Việc có nên đưa các script deploy vào git là quyết định riêng (ưu tiên số 1 của bản đánh giá), chưa làm.

## 4. Lỗi mã thoát 1 của e2e — ĐÃ SỬA

Hiện tượng (ghi nhận từ DEV-117→120): `npx jest --config jest.e2e.config.js` báo 36/36 suite, 401/401 test PASS nhưng **mã thoát 1** → sẽ làm CI luôn đỏ.

Cách khoanh vùng: chạy riêng từng file (36 file đều exit 0) → chỉ lỗi khi chạy chung; `--json` cho thấy chính Jest báo `success: true` (0 test hỏng, 0 lỗi runtime, không ngắt, không handle treo) → có thứ đặt `process.exitCode = 1` trong lúc chạy. `jest.e2e.config.js` có `maxWorkers: 1` nên các file chạy CHUNG một process.

**Nguyên nhân (1 gốc, 2 đường):** `shared/performance/performanceLogBuffer.ts` có bộ hẹn giờ 10 giây (`setInterval`, đã `unref`) ghi log hiệu năng xuống DB. Khi một file test xong mà bộ đệm còn dữ liệu, bộ hẹn giờ chạy SAU khi file đó đã dọn — giữa lúc file khác đang chạy:
1. Với file có DB: ghi vào DB đã tắt → `console.error("[performanceLogBuffer] Flush thất bại")` → Jest báo *"Cannot log after tests are done"* (27 lần mỗi lượt chạy) và đặt mã thoát 1.
2. Với `api-docs-toggle.e2e-test.ts` (không DB, nạp app 3 lần bằng `jest.resetModules()`): mongoose nạp module sau khi môi trường Jest của file đã dọn → *"You are trying to `import` a file after the Jest environment has been torn down"* → Jest cũng đặt mã thoát 1.

**Sửa (chỉ trong test, không đổi code production):**
- `src/__tests__/e2e/setup.ts` — `stopE2EDatabase()` gọi `flushPerformanceLogBuffer()` TRƯỚC khi xoá/ngắt DB, đúng như graceful shutdown thật (`config/database/database.shutdown.ts`). Import động để không nạp module app trước khi `startE2EDatabase` đặt env.
- `src/__tests__/e2e/api-docs-toggle.e2e-test.ts` — `jest.doMock` thay `performanceLogBuffer` bằng bản giả (test chỉ kiểm `/api-docs` bật/tắt).

**Kiểm chứng:** toàn bộ e2e **36 suites / 401 test PASS, exit 0**; số lần "Cannot log after tests are done" 27 → 0; "environment has been torn down" 2 → 0. `api-docs-toggle` riêng: 3/3 PASS.

**Quyết định của user (2026-11-02, sau khi e2e đã sạch):** KHÔNG thêm job e2e vào `ci.yml`. E2E vẫn chạy tay trên máy trước khi bàn giao task (`cd backend && npx jest --config jest.e2e.config.js`, giờ exit 0 khi mọi test PASS).
